# ADR-0007: Субагенты — четыре роли, каждая с замером

|---|---|
| Статус | принято; классификатор — по итогам замера |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | ОМ-4, ДВ-1, ДУ-1, ДУ-2, ТР-5.3, КО-1, КО-2; [ADR-0005](0005-claims-quote-check.md), [ADR-0008](0008-routing.md), [ADR-0009](0009-hooks-accelerators.md), [ADR-0011](0011-data-safety.md) |

## Контекст
Задание прямо говорит: число агентов само по себе не преимущество. Мультиагентные системы тратят примерно в 15 раз больше токенов, чем чат, и окупаются на ценных задачах, которые хорошо делятся на части ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Независимая проверка ценна, потому что модель выше оценивает собственные тексты ([MT-Bench](https://arxiv.org/abs/2306.05685)). Граница прав — главная защита от инъекций: в одной роли не сочетаются недоверенный вход, доступ к чувствительному и изменение состояния ([правило двух](https://ai.meta.com/blog/practical-ai-agent-security/)). Что умеют среды (обращение 04.11.2026):
- Claude Code: поле `tools` принимает имена инструментов, а не шаблоны команд, поэтому Bash одной командой ограничивается хуком ([субагенты](https://code.claude.com/docs/en/sub-agents));
- Cursor читает `.claude/agents` без поля `tools`, зато с полем `readonly` ([Cursor](https://cursor.com/docs/context/subagents));
- OpenCode использует свой формат ([OpenCode](https://opencode.ai/docs/agents/)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Без субагентов | Дёшево | Нет независимой проверки, нет границы прав для веба |
| Пять ролей: исследователь, классификатор, красная команда, синтетический респондент, судья полноты | Каждая задача отдельно | Красная команда и судья — оба критики одного выхода; лишняя роль |
| Четыре роли: исследователь, критик в двух режимах, классификатор, синтетический респондент | Меньше компонентов, та же независимость | Критику нужен ясный выбор режима |

## Решение
| Роль | Права | Зачем |
|---|---|---|
| Исследователь | Поиск, чтение файлов проекта, Bash только для `uv run strateg fetch` | Изоляция веба от состояния, чистый контекст на вопрос плана |
| Критик: режим «возражения» и режим «полнота» | Только чтение | Сильные возражения к вариантам; проверка выхода по рубрике |
| Классификатор | Только чтение пар «утверждение — цитата» | Подтверждает ли цитата утверждение по смыслу, верен ли тип |
| Синтетический респондент | Без инструментов | Беседа в заданной роли для поиска гипотез; каждый ответ — «синтетика» |

- **Тексты ролей** лежат в `knowledge/roles/`. Файлы `.claude/agents/*.md` — тонкие обёртки: права, `model: inherit` и ссылка на текст роли. Для Cursor у всех ролей, кроме исследователя, стоит `readonly`.
- **Модель роли** задаёт только `config/routing.yaml` ([ADR-0008](0008-routing.md)). Скилл узнаёт её командой `strateg route <роль>` и передаёт при запуске субагента.
- **Права исследователя.** В Claude Code Bash ограничивает хук в описании субагента: проходит только `uv run strateg fetch`. Чтение `~/.strateg/` и `.env` запрещено правилом прав. Где ограничить Bash нельзя, например в Cursor с `readonly`, исследователь возвращает список адресов. Скачивает их основной агент через `strateg fetch`, а исследователь читает готовые снимки.
- **Без субагентов.** Скилл исполняет роль в основном контексте и помечает результат «проверка не независимая».
- **Ограничение.** Критик — та же семья моделей, что и основной агент, поэтому самопредпочтение уменьшается, но не исчезает. Так и записано в отчёте о прогоне.

## Последствия
- Проще: веб изолирован; проверка не делается тем же контекстом, что и работа.
- Сложнее: протокол передачи результатов (утверждения с цитатами и `locator`) должен быть одинаков для всех ролей.
- Нужно сделать: обёртки ролей, хук ограничения Bash, размеченная выборка из 50 пар «утверждение — цитата», тестовая страница с инструкцией.

## Польза и замер
- Какую пользу ждём: исследователь — инструкции со страниц не доходят до состояния, основной контекст меньше; критик — возражения сильнее, полнота выше; классификатор — дешёвая проверка смысла цитаты; респондент — гипотезы для интервью без выдачи синтетики за факт.
- Как замеряем:
  - обязательно — точность классификатора против ручной разметки и против Sonnet при цене; отрицательный тест «факт из синтетики»; тест со страницей-инъекцией;
  - по остатку лимита — абляции на кейсах: без критика и без исследователя (веб в основном контексте). Список — в [ADR-0015](0015-evaluation.md).
- Результат замера: ожидается.
- Если пользы нет: классификатор с точностью ниже 90 % или не дешевле Sonnet убираем, второй слой проверки делает критик. Если абляция не покажет пользы критика, он остаётся только в режиме «полнота».
