# ADR-0007: Субагенты — четыре роли, каждая с замером

| | |
|---|---|
| Статус | принято; классификатор — по итогам замера |
| Дата | 06.11.2026 |
| Кто решил | команда проекта |
| Связано | ОМ-4, ДВ-1, ДУ-1, ДУ-2, ТР-5.3, КО-1, КО-2; [ADR-0005](0005-claims-quote-check.md), [ADR-0008](0008-routing.md), [ADR-0009](0009-hooks-accelerators.md), [ADR-0011](0011-data-safety.md), [ADR-0013](0013-mcp.md) |

## Контекст
Задание прямо говорит: число агентов само по себе не преимущество. Мультиагентные системы тратят примерно в 15 раз больше токенов, чем чат, и окупаются на ценных задачах, которые хорошо делятся на части ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Независимая проверка ценна, потому что модель выше оценивает собственные тексты ([MT-Bench](https://arxiv.org/abs/2306.05685)). Граница прав — главная защита от инъекций: в одной роли не сочетаются недоверенный вход, доступ к чувствительному и внешний канал ([правило двух](https://ai.meta.com/blog/practical-ai-agent-security/)). Что умеют среды (обращение 04.11.2026):
- Claude Code: поле `tools` принимает имена инструментов, а не шаблоны команд. Хуки из описания субагента в `claude -p` не исполняются, а хуки из `.claude/settings.json` исполняются ([субагенты](https://code.claude.com/docs/en/sub-agents), [хуки](https://code.claude.com/docs/en/hooks));
- запрет одного WebFetch не закрывает сеть: остаются команды Bash ([права](https://code.claude.com/docs/en/permissions));
- Cursor читает `.claude/agents` без поля `tools`, зато с полем `readonly` ([Cursor](https://cursor.com/docs/context/subagents)); OpenCode использует свой формат ([OpenCode](https://opencode.ai/docs/agents/)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Без субагентов | Дёшево | Нет независимой проверки, нет границы прав для веба |
| Пять ролей: исследователь, классификатор, красная команда, синтетический респондент, судья полноты | Каждая задача отдельно | Красная команда и судья — оба критики одного выхода; лишняя роль |
| Четыре роли: исследователь, критик в двух режимах, классификатор, синтетический респондент | Меньше компонентов, та же независимость | Критику нужен ясный выбор режима |

## Решение
| Роль | Права | Зачем |
|---|---|---|
| Исследователь | Поиск; чтение только `projects/<id>/sources/` и `knowledge/`; Bash — только точная команда `uv run strateg fetch <адрес>`; Playwright — только переход и снимок экрана по адресам человека ([ADR-0013](0013-mcp.md)) | Весь веб — в одной роли без доступа к чувствительному |
| Критик: режим «возражения» и режим «полнота» | Только чтение выводов проекта; в режиме «полнота» — ещё снимков `sources/`, чтобы сверить цитату со смыслом и заявления страницы | Сильные возражения к вариантам; проверка выхода по рубрике |
| Классификатор | Без инструментов: пары «утверждение — цитата» — в задании, которое собирает CLI (`strateg claim pairs`); текст роли — тело обёртки | Подтверждает ли цитата утверждение по смыслу, верен ли тип |
| Синтетический респондент | Без инструментов | Беседа в заданной роли для поиска гипотез; каждый ответ — «синтетика» |

- **Основной агент** выхода в сеть не имеет: ни поиска, ни `WebFetch`, ни `strateg fetch`, ни Playwright. Встроенные субагенты среды ему тоже запрещены. Исследователю он передаёт вопрос плана — формулировку, предмет, период и регион, без данных проекта. Назад получает утверждения с цитатами и номерами снимков, помеченные как недоверенные. С каждым утверждением исследователь передаёт издателя первоисточника, вид источника, признак «о себе» и, если нашёл расхождение, поле «спор» с причиной; «подозрительный» и число независимых первоисточников добавляет CLI ([ADR-0005](0005-claims-quote-check.md)).
- **Пре-мортем.** После выбора варианта на В4 критик в режиме «возражения» получает задание: «прошёл год, вариант провалился — назови три причины». Причины — гипотезы с сигналом и порогом ([ADR-0016](0016-decisions-follow-up.md)). Новой роли для этого нет.
- **Тексты ролей** лежат в `knowledge/roles/`. Файлы `.claude/agents/*.md` — тонкие обёртки: права, `model: inherit`, ссылка на текст роли. У классификатора инструментов нет, и прочесть ссылку он не может: тело его обёртки — сам текст роли (копия, совпадение сверяет тест). Для Cursor у всех ролей, кроме исследователя, стоит `readonly`.
- **Права держит одно место** — `PreToolUse` в `.claude/settings.json` с проверкой `agent_type` ([ADR-0009](0009-hooks-accelerators.md)). Хуков в описании субагентов нет: они не работают в `claude -p`, а на стенде граница должна быть та же.
- **Модель роли** задаёт только `config/routing.yaml` ([ADR-0008](0008-routing.md)). Хук на запуск субагента подставляет её сам, поэтому выбор не зависит от памяти модели.
- **Без границы прав.** В Cursor субагенты есть, но права по ролям хук не держит: `agent_type` во входе не подтверждён. Проверка там независима по контексту, но не по правам, и отчёт о прогоне пишет «граница прав не активна». Где субагентов нет, как в OpenCode, скилл исполняет роль в основном контексте и помечает результат «проверка не независимая».
- **Ограничение.** Критик — та же семья моделей, что и основной агент, поэтому самопредпочтение уменьшается, но не исчезает. Так и записано в отчёте о прогоне.
- **Классификатор.** Он тоже той же семьи моделей: его независимость — в контексте, а не в модели. Он видит только пары, без хода работы и выводов проекта. Проверяет все пары на шаге 3 и основания без вердикта на шаге 6 ([ADR-0005](0005-claims-quote-check.md)). Цитата в задании — одна строка в кавычках с меткой «недоверенный текст». Вердикт записывает CLI (`strateg claim verdict`): ответ разбирается строго, неразобранная пара — «не уверен». «Не подтверждает» не даёт утверждению стать основанием рекомендации, обещания, решения или довода `why`, пока его не заменят или не отзовут. «Не уверен» — повтор этих пар на средней модели ([ADR-0008](0008-routing.md)). Вызов роли подтверждает событие «роль выполнена» от хука `SubagentStop`, как у критика; без него вердикт помечен «вызов классификатора не подтверждён».

## Последствия
- Проще: весь веб в одной роли без чувствительного; проверка не делается тем же контекстом, что и работа.
- Сложнее: протокол передачи результатов — утверждения с цитатами, `locator`, номером снимка и полями источника — одинаков для всех ролей.
- Сделано: обёртки ролей; правила хука; тесты «исследователь вызывает `curl` — отказ», «исследователь читает `inputs/` — отказ», «основной агент запускает встроенный субагент — отказ», страница-инъекция. Классификатор: `claim pairs`, `claim verdict`, последствия в `check` и `status`; хук отказывает роли в каждом инструменте, для которого вызывается (две записи `matcher`: файлы, оболочка, субагенты, веб, Playwright, остальные MCP, `Skill`, `SendMessage`, ресурсы MCP), остальные инструменты закрывает только `tools: []` обёртки; размеченные выборки `evals/classifier/pairs.yaml` (52 пары) и `evals/classifier/holdout.yaml` (контрольная, составлена без знакомства с текстом роли), скрипт замера `scripts/eval_classifier.py`; тест разбора и правила на заготовленных ответах, в том числе с инструкцией в цитате.

## Польза и замер
- Какую пользу ждём: исследователь — инструкции со страниц не доходят до состояния, основной контекст меньше; критик — возражения сильнее, полнота выше; классификатор — дешёвая проверка смысла цитаты; респондент — гипотезы для интервью без выдачи синтетики за факт.
- Как замеряем:
  - обязательно — точность классификатора против ручной разметки и против Sonnet при цене; отрицательный тест «факт из синтетики»; тесты прав и страница-инъекция на стенде;
  - по остатку лимита — абляции на кейсах: без критика и без исследователя. Список — в [ADR-0015](0015-evaluation.md).
- Что меряем у классификатора: связку, как роль работает в продукте, — дешёвая модель на всех парах одним заданием, пары «не уверен» — повтор на средней. Одиночная дешёвая модель — справочно: её честное «не уверен» в связке не ошибка.
- Результат замера: ожидается; скрипт и выборки — `scripts/eval_classifier.py`, `evals/classifier/pairs.yaml` и `evals/classifier/holdout.yaml`: точность по вердикту и типу против разметки, ложные «подтверждает», согласие с Sonnet, «не уверен» от модели и неразобранные, доля повторов, цена пары по `total_cost_usd`, пары, где эталон расходится с обеими моделями.
- Если пользы нет: связку классификатора, у которой на основной или контрольной выборке точность ниже 90 %, ложных «подтверждает» больше одного или цена пары не ниже Sonnet, убираем; второй слой проверки делает критик. Если абляция не покажет пользы критика, он остаётся только в режиме «полнота».

## Изменения
- 06.11.2026: в протокол передачи от исследователя добавлены поля источника, критику — пре-мортем выбранного варианта. Основной агент должен видеть, на чём держится утверждение, а выбор человека проверяется без новой роли.
- 07.11.2026: критик в режиме «полнота» читает снимки `sources/` — без них не проверить вопросы рубрики о смысле цитат и заявлениях страницы. Внешнего канала у критика нет, поэтому правило «не больше двух свойств из трёх» ([ADR-0011](0011-data-safety.md)) соблюдается.
- 15.11.2026: у классификатора нет инструментов (`tools: []` в обёртке, любой вызов закрывает хук). Поэтому текст роли он получает в задании: `strateg claim pairs --json` собирает его вместе с парами, и замер шлёт моделям то же задание. Пары и вердикты даёт и пишет CLI.
- 17.11.2026: текст роли классификатора — тело обёртки, задание несёт только пары: иначе основной агент переписывал бы роль в каждый вызов выходными токенами основной модели. Замер шлёт роль системным промптом. Правило «Если пользы нет» относится к связке «дешёвая + повтор на средней», а ложные «подтверждает» — отдельное условие: так роль работает в продукте, и самая дорогая ошибка в правиле участвует. Контрольная выборка — потому что примеры роли раньше совпадали с выборкой. Хук получил вторую запись `matcher`: прежняя не видела большую часть MCP и ряд встроенных инструментов.
- 18.11.2026: роль респондента сделана. Без инструментов, как у классификатора: текст `knowledge/roles/respondent.md` — тело обёртки `.claude/agents/respondent.md` (совпадение сверяет тест), задание несёт только персону и вопросы, а хук отказывает роли в любом инструменте (правило `respondent` рядом с правилом классификатора, обе записи `matcher`). Каждый ответ начинается с «СИНТЕТИКА». Беседу записывает `strateg synth add`: источник вида «синтетика» со снимком и `sha256`, вызов роли подтверждает событие «роль выполнена», иначе сессия помечена «не подтверждён». Утверждения на ней — только типа «синтетика», а поле, где она стоять не может (основание рекомендации, её `why`, обещание, решение, показатель, пре-мортем, `closed_by`), — ошибка `check`. Три персоны берутся из рамки и картины ситуации; подробности — в `knowledge/methods/interviews.md`.
