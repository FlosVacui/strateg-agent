# ADR-0003: Проект — папка, знания разделены по слоям

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-2, УА-3, ДВ-4, ДВ-6, ДУ-6, ТР-5.4; [ADR-0002](0002-cli-single-interface.md), [ADR-0011](0011-data-safety.md) |

## Контекст
Задание требует хранить раздельно постоянные инструкции, методические знания, материалы проекта и состояние задачи. Проект должен переноситься на другой компьютер и в другую среду. Проекты пользователя в git не попадают, поэтому передача идёт архивом, а прежние версии выводов git не хранит.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Всё в одном файле состояния | Просто читать | Растёт без меры, правки конфликтуют, нечего проверять схемой |
| База данных SQLite как основное хранилище | Запросы, целостность | Человек не прочтёт; хуже для переноса |
| Папка проекта: YAML для того, что читает человек, JSONL для журналов; методика и правила — вне проекта | Читаемо, проверяемо схемами, переносится архивом | Нужны схемы, проверка и свои версии |

## Решение
| Слой | Где | Кто пишет |
|---|---|---|
| Постоянные инструкции | `AGENTS.md`, `CLAUDE.md`, скиллы, субагенты | Разработчики агента |
| Методические знания | `knowledge/`: методы, шаблоны, рубрики, тексты ролей, источники по умолчанию | Разработчики агента |
| Материалы проекта | `projects/<id>/inputs/` — материалы человека и извлечённый из них текст; `projects/<id>/sources/` — только снимки из веба: страницы и снимки экрана | Человек кладёт материалы; текст и снимки пишет CLI |
| Состояние задачи | `state.yaml`, `frame.yaml`, `journal.jsonl`, `cost.jsonl` | Только CLI |
| Выводы | Реестр утверждений, картина, варианты, стратегии, решения, расчёты | Скиллы через CLI; расчёты — скриптами в папке проекта |

- **Веб и материалы человека лежат раздельно.** Реестр источников общий, а файлы — в разных папках: в `sources/` только то, что пришло из веба. Исследователь читает только `sources/` и методику, поэтому материалов человека не видит ([ADR-0011](0011-data-safety.md)).
- **Снимок без записи — потеря.** Файл `sources/i-<n>.txt`, на который не ссылается ни одна запись `sources.yaml`, `check` называет ошибкой: так видна запись, которую затёрла параллельная команда ([ADR-0002](0002-cli-single-interface.md)). Другие имена в `sources/` (мусор ОС, временные файлы записи) не в счёт; в `inputs/` потерь `check` не ищет, там лежат файлы человека. Номер нового источника обходит номера, занятые таким файлом, и занятый файл не перезаписывается.
- **Рамка задачи** — отдельный файл `frame.yaml`: её видно и легко сверить.
- **Версии.** Перед перезаписью рамки, плана или документа вывода CLI кладёт прежнюю версию в `history/` рядом с файлом. Так работают «было → стало» и «прежние документы доступны».
- **Пути и формат.** Пути внутри проекта только относительные, кодировка UTF-8, окончания строк LF.
- **Расчёты** по таблицам — скрипты в папке проекта, повторяются одной командой.
- **Исходники с персональными данными** после обезличивания CLI переносит вне репозитория — в папку пользователя `~/.strateg/private/<id>/`. Она вне рабочей папки среды, чтение её запрещено правилом прав и хуком, и она не попадает ни в git, ни в архив проекта ([ADR-0011](0011-data-safety.md)).
- **Передача и пример.** Упаковка для передачи — `strateg pack`. Пример продолжается на копии: `strateg new <id> --from example` копирует папку без `.tmp/` и кэша, меняет номер, пересчитывает хеши и пишет событие «копия проекта»; `cost.jsonl` копии пуст, время считается от события, пример не меняется ни на байт.
- **Форматы файлов** задаёт описание модели данных `docs/data-model.md`, CI сверяет схемы с моделями.

## Последствия
- Проще: человек читает выводы без инструментов; перенос — архив папки; признаки сценариев проверяются по файлам.
- Сложнее: нужны схемы, тесты на них и версии в `history/`.
- Нужно сделать: схемы, команды `pack` и `new --from`, запись версий.

## Польза и замер
- Какую пользу ждём: порядок в знаниях виден проверяющему; проект переносится без потерь.
- Как замеряем: сценарий С-14 — архив распакован на другой ОС, `strateg status` даёт ту же сводку, в архиве нет правил, методики, исходников с ПДн и абсолютных путей; С-4 и С-5 — прежняя версия документа доступна.
- Результат замера: ожидается.
- Если пользы нет или не успеваем: сокращаем число файлов выводов, версии хранятся только для рамки и стратегий. Слои не сливаем — этого требует задание.
