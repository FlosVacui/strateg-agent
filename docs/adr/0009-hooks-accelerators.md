# ADR-0009: Хуки Claude Code — ускорители и страховка

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-3, ДУ-2, ДУ-5, ТР-3, ТР-5.2, ТР-5.3; [ADR-0002](0002-cli-single-interface.md), [ADR-0007](0007-subagents.md), [ADR-0010](0010-cost-budget.md), [ADR-0011](0011-data-safety.md) |

## Контекст
Хуки срабатывают по событиям Claude Code. В других средах их нет или набор событий урезан. Факты из [документации хуков](https://code.claude.com/docs/en/hooks) (обращение 04.11.2026):
- `SessionStart` с источником `startup`, `resume`, `clear` или `compact` может вернуть контекст в сессию;
- `PreCompact` вернуть контекст не может;
- `PreToolUse` может запретить вызов инструмента; внутри субагента во входе хука есть `agent_type`;
- `PostToolUseFailure` получает ошибку инструмента;
- поведение при сбое самого хука задаётся явно полем `onFailure`;
- правила `permissions.deny` сильнее разрешения хука, но не закрывают чтение файла командами без его имени ([права](https://code.claude.com/docs/en/permissions)).

На Windows хуки лучше писать на Python и задавать пути с прямыми слэшами.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Без хуков | Одинаково везде | Сводку при старте, учёт ошибок и бюджет держит только инструкция |
| Хуки как опора корректности | Автоматически | Без Claude Code ломается |
| Хуки вызывают тот же CLI, что и скиллы, и страхуют права | Ускоряют и страхуют, корректность не зависит от них | Двойной путь надо держать в согласии |

## Решение
| Событие и matcher | Что делает | При сбое хука |
|---|---|---|
| `SessionStart`: `startup`, `resume`, `clear`, `compact` | `strateg status --brief` — сводка «где остановились» в контекст | не блокирует |
| `PreCompact` | `strateg checkpoint` — контрольная точка перед сжатием | не блокирует |
| `PreToolUse`: `Edit`, `Write`, `Read`, `Bash`, `Agent`, `WebSearch`, `WebFetch`, инструменты Playwright | Охрана — см. ниже | блокирует |
| `PostToolUseFailure` | `strateg event error` — ошибка инструмента в журнал | не блокирует |
| `Stop` | `strateg checkpoint` и учёт стоимости по транскрипту ([ADR-0010](0010-cost-budget.md)), без блокировки ответа | не блокирует |

**Охрана `PreToolUse`:**
- запрет правок `AGENTS.md`, `CLAUDE.md`, `.claude/`. Для разработки самого агента охрана правил выключается переменной `STRATEG_DEV=1`, остальные запреты действуют;
- запрет чтения `.env` и `~/.strateg/`; то же в `permissions.deny`;
- `WebSearch` и `WebFetch` — только внутри исследователя (по `agent_type`); у основного агента веба нет;
- инструменты Playwright — только для адресов из списка разбора интерфейсов, который ведёт CLI ([ADR-0013](0013-mcp.md));
- Bash у исследователя — только `uv run strateg fetch`;
- при исчерпанном бюджете — отказ всем инструментам, кроме команд `strateg` и записи выпуска с пометкой о неполноте.

Разбор команд Bash ловит явные записи в охраняемые пути, но не все. Поэтому охрана правил **снижает риск**, а не гарантирует защиту.

Хуки — короткие скрипты Python в `.claude/hooks/`, запуск через `uv run` с `PYTHONUTF8=1`. Задержку на вызов проверяем при сборке хуков. Всё, что делают хуки для состояния, скиллы умеют сделать и сами, вызовом CLI.

## Последствия
- Проще: в Claude Code продолжение и учёт ошибок идут сами; веб, правила и данные охраняются правами.
- Сложнее: два пути к одному CLI; хуки надо тестировать на Windows и macOS; разработчикам нужен `STRATEG_DEV=1`.
- Нужно сделать: скрипты хуков; тесты «правка AGENTS.md запрещена», «основной агент не вызывает WebFetch», «бюджет исчерпан — отказ»; тест на ошибку инструмента.

## Польза и замер
- Какую пользу ждём: меньше пропусков в журнале и быстрее продолжение в Claude Code, чем в среде без хуков; веб не доходит до основного агента.
- Как замеряем: сценарии С-2 и С-9 в Claude Code и в Cursor — доля ошибок, попавших в журнал, число сообщений человека до продолжения; тест со страницей-инъекцией — дошёл ли её текст до основного агента.
- Результат замера: ожидается.
- Если пользы нет: остаются только охрана прав и `.env`, остальные хуки убираем.
