# ADR-0002: CLI `strateg` — единственный путь изменения состояния

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-3, УА-4, ДУ-3, ДУ-5, ТР-2, КО-3; [ADR-0003](0003-project-folder-layers.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Работа должна продолжаться после перерыва без незаметного повтора выполненного, в том числе в новом чате и в другой среде. Хуки есть только в Claude Code. Модель может ошибиться в арифметике, формате файла или порядке записи. Правило, которое должно соблюдаться всегда, нельзя доверять одному тексту инструкции ([документация скиллов](https://code.claude.com/docs/en/skills)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Модель сама пишет файлы проекта по инструкции | Ничего не надо писать | Ошибки формата, повторы, выдуманные числа; поведение зависит от среды |
| Хуки Claude Code следят за состоянием | Автоматически | Только в Claude Code |
| CLI на Python — единственный путь записи состояния; скиллы и хуки вызывают его | Одинаково в любой среде, проверяемо тестами | Нужно написать и поддерживать CLI |
| Свой MCP-сервер | Удобные инструменты | Не во всех средах настраивается одинаково, дороже в разработке |

## Решение
Всё, что меняет состояние проекта, делает CLI `strateg`: журнал, отметки выполнения, рамка, план, источники, утверждения, решения, затраты, бюджет. Скиллы вызывают его командами `uv run strateg …`, хуки — тем же CLI. Команды выдают понятный текст по-русски, а с `--json` — машинный вывод.

У каждого действия есть ключ идемпотентности:
- детерминированное действие — хеш команды и входов, например `fetch` и адрес;
- шаг с моделью — шаг, номер вопроса плана и версия рамки;
- `claim add` — хеш текста, источника и цитаты; повтор не создаёт дубля. Утверждение хранит шаг, вопрос плана и номер попытки. При повторе прерванного шага CLI отдаёт скиллу уже записанные утверждения по шагу и вопросу, и скилл дописывает недостающие, а не формулирует заново.

Перед выполнением CLI ищет ключ в журнале и пропускает сделанное. Действие с началом и без отметки выполнения при продолжении получает событие «прервано» и выполняется заново. Свой MCP-сервер — только тонкая обёртка над CLI и первый пункт списка урезания.

## Последствия
- Проще: продолжение после перерыва и учёт не зависят от среды и от внимательности модели; поведение покрыто тестами.
- Сложнее: каждый скилл должен вызывать CLI в нужных местах; вне Claude Code пропуск вызова страхует только отказ CLI на следующей границе шага.
- Нужно сделать: команды из [архитектуры](../architecture.md#4-cli-модули-c4-уровень-3), тесты на идемпотентность и прерывание.

## Польза и замер
- Какую пользу ждём: ноль повторов после перерыва, одинаковый журнал в разных средах.
- Как замеряем: сценарий С-2 — повторные отметки выполнения и дубли утверждений; тот же сценарий в среде без хуков; прерывание процесса после заданного по счёту `fetch` и после части `claim add`.
- Результат замера: ожидается.
- Если пользы нет или не успеваем: CLI сокращается до журнала с ключами, `fetch` и `status`. Утверждения и решения скиллы пишут по схеме сами, CLI их только проверяет.
