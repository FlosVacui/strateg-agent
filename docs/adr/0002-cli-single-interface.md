# ADR-0002: CLI `strateg` — единственный путь изменения состояния

| | |
|---|---|
| Статус | принято |
| Дата | 06.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-3, УА-4, ДУ-3, ДУ-5, ТР-2, КО-3; [ADR-0003](0003-project-folder-layers.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Работа должна продолжаться после перерыва без незаметного повтора выполненного, в том числе в новом чате и в другой среде. Хуки есть только в Claude Code. Модель может ошибиться в арифметике, формате файла или порядке записи. Правило, которое должно соблюдаться всегда, нельзя доверять одному тексту инструкции ([документация скиллов](https://code.claude.com/docs/en/skills)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Модель сама пишет файлы проекта по инструкции | Ничего не надо писать | Ошибки формата, повторы, выдуманные числа; поведение зависит от среды |
| Хуки Claude Code следят за состоянием | Автоматически | Только в Claude Code |
| CLI на Python — единственный путь записи состояния; скиллы и хуки вызывают его | Одинаково в любой среде, проверяемо тестами | Нужно написать и поддерживать CLI |
| Свой MCP-сервер | Удобные инструменты | Не во всех средах настраивается одинаково, дороже в разработке |

## Решение
Всё, что меняет состояние проекта, делает CLI `strateg`: журнал, отметки выполнения, рамка, план, источники, утверждения, решения, затраты, бюджет. Скиллы вызывают его командами `uv run strateg …`. Хуки пишут журнал тем же кодом CLI, без запуска команды: отказ и задание исследователю записываются за 0,25 с вместо 1,1 с. Журнал и `state.yaml` пишутся под блокировкой папки проекта (файл `.tmp/lock`, в архив не попадает), поэтому одновременная запись хука и команды не теряет событий и не даёт ложного «изменено вне агента». Команды выдают понятный текст по-русски, а с `--json` — машинный вывод.

**Параллельные команды.** Команда, которая меняет проект, держит блокировку папки на всё изменение: от чтения состояния до последней записи (`transaction` в `src/strateg/project.py`). Проект, открытый до блокировки, для записи не годится: под блокировкой он перечитывается, и номер `И-n` или `У-n`, повтор и запись строятся по тому, что лежит в папке сейчас, а не по снимку, снятому при открытии команды. Реестры `sources.yaml` и `claims.yaml` пишутся целиком, поэтому `save_sources` и `save_claims` вне блокировки отказывают. Откат после ошибки идёт под той же блокировкой и записей соседей не стирает.
- **До блокировки — долгая работа:** разбор аргументов и входных файлов, сеть (`fetch`), извлечение текста из PDF, DOCX, XLSX и PPTX, проверки текста материала. Параллельные исследователи не ждут чужих запросов.
- **Под блокировкой — только сверка и запись:** сверка с реестром, номер, проверка цитат по снимкам, запись файлов и событий. `fetch` идёт в три приёма: под блокировкой решить и записать «начато»; без блокировки скачать и разобрать страницу; под блокировкой заново сверить адрес и текст, взять номер, записать снимок и источник ([ADR-0004](0004-sources-snapshots.md)). Так же `add` заново сверяет файл по sha256 перед номером.
- **Срок ожидания:** CLI ждёт блокировку 30 с (`LOCK_TIMEOUT`), хук — 5 с на запись (`HOOK_LOCK_TIMEOUT`), и каждый хук в сумме меньше своего тайм-аута в настройках (15 с): `Stop` и `SubagentStop` делят один срок 9 с на все записи, `SessionStart` и `PostToolUseFailure`, которые идут через CLI, ждут 10 с на открытие проекта и запись вместе. Момент окончания считается один раз в начале хука (`storage.deadline`), каждый следующий захват папки ждёт только остаток. На проекте в 25 источников и 60 утверждений блокировку держат: `fetch` — около 0,2 с на команду (три захвата), `claim add` — 0,2–0,8 с (растёт с числом утверждений), проверка проекта внутри блокировки — 0,17 с. Пять параллельных исследователей по четыре `fetch` вместе с хуками отказов «папка занята» не получили, хук ждал не дольше 1,5 с. Хук, которому папку не отдали за 5 с, пропускает запись и называет потерянное событие в стандартном выводе ошибок; стоимость не теряется: следующий учёт читает транскрипт от записанного смещения ([ADR-0010](0010-cost-budget.md)).

У каждого действия есть ключ идемпотентности:
- детерминированное действие — хеш команды и входов, например `fetch` и адрес;
- шаг с моделью — шаг, номер вопроса плана и версия рамки;
- `claim add` — хеш текста, источника и цитаты; повтор не создаёт дубля. Утверждение хранит шаг, вопрос плана и номер попытки. При повторе прерванного шага CLI отдаёт скиллу уже записанные утверждения по шагу и вопросу, и скилл дописывает недостающие, а не формулирует заново.

Перед выполнением CLI ищет ключ в журнале и пропускает сделанное. Действие с началом и без отметки выполнения при продолжении получает событие «прервано» и выполняется заново. Своего MCP-сервера нет (ADR-0013): CLI доступен из любой среды через Bash.

## Последствия
- Проще: продолжение после перерыва и учёт не зависят от среды и от внимательности модели; поведение покрыто тестами.
- Сложнее: каждый скилл должен вызывать CLI в нужных местах; вне Claude Code пропуск вызова страхует только отказ CLI на следующей границе шага.
- Нужно сделать: команды из [архитектуры](../architecture.md#4-cli-модули-c4-уровень-3), тесты на идемпотентность и прерывание.

## Польза и замер
- Какую пользу ждём: ноль повторов после перерыва, одинаковый журнал в разных средах.
- Как замеряем: сценарий С-2 — повторные отметки выполнения и дубли утверждений; тот же сценарий в среде без хуков; прерывание процесса после заданного по счёту `fetch` и после части `claim add`.
- Результат замера: ожидается.
- Если пользы нет или не успеваем: CLI сокращается до журнала с ключами, `fetch` и `status`. Утверждения и решения скиллы пишут по схеме сами, CLI их только проверяет.

## Изменения
- 06.11.2026: своего MCP-сервера нет — согласовано с ADR-0013.
- 08.11.2026: журнал пишут CLI и хук — общим кодом с блокировкой папки проекта ([ADR-0009](0009-hooks-accelerators.md)).
- 15.11.2026: изменяющая команда держит блокировку на всё изменение, а не на отдельные записи; проект для записи перечитывается под ней. Ограничение «две одновременные команды могут перезаписать файл друг друга» снято. Срок ожидания CLI — 30 с вместо 10 с, отдельного срока отката нет.
