# ADR-0010: Учёт затрат и бюджет

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-4, ТР-3, СД-4.5, КО-4; [ADR-0008](0008-routing.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Задание требует знать полную стоимость результата: модели, поиск, инструменты, повторы и доработку человеком. Где стоимость видна (обращение 04.11.2026):
- в интерактивном Claude Code — в строке статуса: поле `cost.total_cost_usd`, клиентская оценка, сбрасывается при `/clear` ([строка статуса](https://code.claude.com/docs/en/statusline)); документация описывает строку статуса в терминале, работа в расширении VS Code не подтверждена;
- в хуках поля стоимости нет, но есть `transcript_path` — путь к транскрипту с токенами ([хуки](https://code.claude.com/docs/en/hooks));
- в `claude -p` — `total_cost_usd` и `modelUsage` с субагентами; при `--resume` итог накопительный ([headless](https://code.claude.com/docs/en/headless));
- в других средах — токены, если среда их отдаёт.

На подписке счёт идёт долями лимита, а не долларами.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Не считать | Просто | Нарушает задание |
| Модель сама оценивает расход | Везде | Выдуманные числа |
| Адаптер учёта из нескольких источников; у каждой записи источник и точность | Честно, везде что-то есть | Разная точность в разных средах |

## Решение
**Источники стоимости:**

| Среда | Источник | Точность |
|---|---|---|
| Стенд `claude -p` | `total_cost_usd` и `modelUsage`; при `--resume` берётся последнее значение | оценка среды |
| Claude Code интерактивно | хук `Stop` суммирует токены транскрипта по таблице цен `config/prices.yaml`; строка статуса, если она есть в этом интерфейсе, даёт `cost.total_cost_usd` для сверки | оценка |
| Другие среды | токены × таблица цен, если среда их отдаёт; иначе «нет данных» | оценка или нет данных |

- **Проект и сессия.** CLI хранит активный проект. Записи стоимости идут в его `cost.jsonl` с `session_id`. По каждой сессии берётся последнее значение, сессии складываются. После `/clear` начинается новая сессия.
- **Подписка.** Показывается эквивалент по цене API с пометкой «оценка» и доля лимитов, если среда её отдаёт.
- **Бюджет** — деньги и время работы агента, по умолчанию из `config/defaults.yaml`; значения задаются по замеру первого прогона. Время работы — сумма длительностей действий из журнала без ожидания ответа на воротах. Если стоимость неизвестна, лимит действует только по времени.
- **Кто держит бюджет.** В Claude Code — хук: при исчерпании он отказывает всем инструментам, кроме команд `strateg` и записи выпуска с пометкой о неполноте ([ADR-0009](0009-hooks-accelerators.md)). В других средах — обязательство скилла вызывать `budget check` перед платным действием и отказ CLI на ближайшей границе шага. Это слабее, и так и написано в отчёте о прогоне.
- **Отчёт о прогоне** собирает время, стоимость по шагам, повторы, сбои, ожидание ответа на воротах и правки человека.

## Последствия
- Проще: руководитель и жюри видят цену результата с указанием, насколько она точна.
- Сложнее: таблицу цен надо держать с датой обращения; точность разная по средам.
- Нужно сделать: хук `Stop` с разбором транскрипта, скрипт строки статуса, `prices.yaml`, `defaults.yaml`, `budget check`, раздел отчёта о прогоне; проверить строку статуса в VS Code.

## Польза и замер
- Какую пользу ждём: известна стоимость каждого проекта; в Claude Code бюджет останавливает работу без участия модели.
- Как замеряем: на стенде — расхождение оценки по транскрипту с `total_cost_usd` того же прогона: так проверяется способ, которым считается интерактивная работа. Сценарий С-13, прогон б, — остановка на 100 % и выпуск с пометкой.
- Результат замера: ожидается.
- Если пользы нет или не успеваем: хранится только итог проекта по транскрипту, без разбивки по шагам; бюджет — только по времени.
