# ADR-0010: Учёт затрат и бюджет

| | |
|---|---|
| Статус | принято |
| Дата | 06.11.2026 |
| Кто решил | команда проекта |
| Связано | УА-4, ТР-3, СД-4.5, КО-4; [ADR-0008](0008-routing.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Задание требует знать полную стоимость результата: модели, поиск, инструменты, повторы и доработку человеком. Где стоимость видна (обращение 04.11.2026):
- в интерактивном Claude Code — в строке статуса: поле `cost.total_cost_usd`, клиентская оценка, сбрасывается при `/clear` ([строка статуса](https://code.claude.com/docs/en/statusline)); работа строки статуса в расширении VS Code не подтверждена;
- в хуках поля стоимости нет, но есть пути к транскриптам: основному — во всех событиях, субагента — в `SubagentStop`. Транскрипт пишется асинхронно и может отставать ([хуки](https://code.claude.com/docs/en/hooks));
- в `claude -p` — `total_cost_usd` и `modelUsage` с субагентами; при `--resume` итог накопительный ([headless](https://code.claude.com/docs/en/headless));
- в других средах — токены, если среда их отдаёт.

В агентной сессии основной объём ввода — чтение из кэша, у него своя цена ([цены](https://platform.claude.com/docs/en/about-claude/pricing)). На подписке счёт идёт долями лимита, а не долларами.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Не считать | Просто | Нарушает задание |
| Модель сама оценивает расход | Везде | Выдуманные числа |
| Адаптер учёта из нескольких источников; у каждой записи источник и точность | Честно, везде что-то есть | Разная точность в разных средах |

## Решение
**Источники стоимости:**

| Среда | Источник | Точность |
|---|---|---|
| Стенд `claude -p` | `total_cost_usd` и `modelUsage`; при `--resume` берётся последнее значение | оценка среды |
| Claude Code интерактивно | Токены основного транскрипта и транскриптов субагентов × таблица цен `config/prices.yaml`: ввод, вывод, запись и чтение кэша по моделям. Строка статуса, если она есть в этом интерфейсе, — для сверки | оценка |
| Другие среды | Токены × таблица цен, если среда их отдаёт; иначе «нет данных» | оценка или нет данных |

- **Когда считается.** `SubagentStop` добавляет стоимость субагента, `Stop` — основного хода. Перед платным вызовом `PreToolUse` пересчитывает расход по транскриптам на текущий момент; перед прочими вызовами, которые исчерпание закрыло бы, — не чаще раза в 5 секунд. Поэтому бюджет срабатывает посреди хода, а не только в конце. Транскрипт субагента лежит отдельно (`<сессия>/subagents/agent-<id>.jsonl`) и в основной не входит, поэтому стоимость не удваивается. `SubagentStop` приходит и от внутренних агентов среды с пустым `agent_type` — их расход идёт с ролью «служебный». Отставание транскрипта страхует лимит по времени. Расход учитывается по id сообщения в транскрипте, поэтому повторный разбор не удваивает его. Если разбор не удался, хук пишет «учёт недоступен» и не блокирует работу ([ADR-0009](0009-hooks-accelerators.md)).
- **Проект и сессия.** CLI хранит активный проект. Записи стоимости идут в его `cost.jsonl` с `session_id` и ролью. По каждой сессии берётся последнее значение, сессии складываются. После `/clear` начинается новая сессия.
- **Таблица цен** `config/prices.yaml`: ключи — id моделей, как они пишутся в транскрипте (`claude-opus-5-5`); цены абсолютные, в USD за миллион токенов: ввод, вывод, запись кэша на 5 минут и на час, чтение кэша; не множители. Чтение кэша у Opus 5.5 и Sonnet 5.5 — 0,05× цены ввода. У Haiku 5.5 цены выше при длине промпта больше 100 000 токенов (считаются все токены ввода, в том числе кэш): порог лежит в файле. Отдельно хранятся цена веб-поиска ($10 за 1000), множители пакетного режима (×0,5) и режима «данные в США» (×1,1), цена быстрого режима Opus 5.5; в файле стоит дата обращения к [странице цен](https://platform.claude.com/docs/en/about-claude/pricing) — 05.11.2026.
- **Веб-поиск.** Вызов `WebSearch` в Claude Code выполняет малая модель, и её токены оплачиваются отдельно от платы за поиск ($10 за 1000). В транскриптах этих токенов нет, а `server_tool_use.web_search_requests` у сообщений нулевой (прогон 08.11.2026: 21 вызов, ноль в поле). Поэтому учёт считает уникальные блоки `tool_use` с именем `WebSearch` в сообщениях ассистента, по id блока, и защищён от повторов так же, как сообщения. Цена вызова — плата за поиск плюс запрос к модели поиска: ключ `web_search_query` в `config/prices.yaml` (модель, средние токены ввода и вывода, дата замера); цена токенов берётся по этой модели из той же таблицы, а не вписана числом. Ключ необязателен: без него таблица цен загружается, поиск считается одной платой за поиск, а `cost report` пишет «модель поиска без цены» рядом со строкой веб-поиска; неизвестная модель в ключе — отказ загрузки. Если в том же сообщении `server_tool_use.web_search_requests` больше нуля, поиски считаются по нему, одной платой: среда уже назвала их сама, второй раз их не считаем. Деньги поиска входят в `cost_usd` записи; её поле `web_search_usd` хранит их долю, а `web_searches` — число поисков, поэтому `cost report` показывает строку «веб-поиск: N вызовов, $X (оценка)» (с падежом: 1 вызов, 2 вызова, 5 вызовов) в итоге и у каждой роли.
- **Точность веб-поиска и сверка.** Это оценка: средний запрос к модели поиска взят из замера и может отличаться (в замере 11 837 токенов ввода и 1 073 вывода на вызов, в таблице округлено до 11 840 и 1 070). Замер: сквозной прогон 08.11.2026 с субагентами, по данным среды 21 поиск у Haiku 5.5, 248 583 токена ввода, 22 529 вывода, 0 кэша — $0,2461 вместе с платой за поиск. Сверка: оценка по транскриптам того же прогона, Sonnet 5.5 $4,9884 и веб-поиск $0,2461, вместе $5,2345 против $5,2346 по данным среды (расхождение 0,002 %). Оговорка: средние токены запроса поиска (11 840 / 1 070) взяты из того же прогона, на котором сделана сверка, поэтому совпадение до 0,002 % не доказывает точность метода; независимая сверка — на следующем прогоне. Модель поиска и её вызовы среда может изменить: если расхождение с данными среды выйдет за 1 %, числа `web_search_query` пересматриваются по новому замеру, дата замера в файле обновляется. Без этой строки расхождение было 4,7 %.
- **Подписка.** Показывается эквивалент по цене API с пометкой «оценка» и доля лимитов, если среда её отдаёт.
- **Бюджет** — деньги и время работы агента, по умолчанию из `config/defaults.yaml`: $8 и 60 минут. Числа заданы по замеру сквозного прогона 08.11.2026 с субагентами: до выпуска без повторной проверки полноты он стоил $5,23 и занял около 25 минут работы; к шестому шагу от прежних $5 оставалось $0,69, и повторную проверку полноты пришлось отбросить. К $5,23 добавляются повторная проверка полноты критиком (около $0,23 за вызов) и поиск по пробелам (исследователь, около $0,13 за вызов), вместе около $1, и запас на материалы человека, повторы и доработку. Если стоимость неизвестна, лимит действует только по времени.
- **Время работы** — сумма длительностей шагов из журнала. Ожидание ответа человека работой не считается: ни на воротах, ни после «внеплановой остановки». Ожидание на воротах кончается по времени ответа (`answered_at`). Ожидание после остановки кончается на ближайшем событии хода проекта: в Claude Code это событие «ответ человека», которое пишет хук `UserPromptSubmit` в момент сообщения человека ([ADR-0009](0009-hooks-accelerators.md)) — работа агента между ответом и первой командой CLI засчитывается (остановка, 900 с ожидания, ответ, 300 с работы без команд, `step done` дают 300 с работы, а не ноль). Без хуков (другие среды) ожидание кончается на первом событии хода, как раньше, и эти секунды теряются. Пересекающиеся ожидания вычитаются один раз. Ход проекта — события журнала без трёх видов: заметок «изменено вне агента», событий хуков (отказ, учёт, бюджет, след роли, граница прав: они приходят и пока человек думает; исключения — «задание исследователю», это работа агента, и «ответ человека», он кончает ожидание после остановки) и «прервано», которое пишет сама сводка. Эти события пауз не снимают, ожидание не обрывают, конец работы прерванного шага и время по часам не сдвигают. Шаг, который ждёт ответа (после его «начато» последнее событие хода проекта — открытые ворота без ответа или остановка), при возобновлении сеанса остаётся «начато»: «прервано» не пишется, повторный `step start` не нужен. Настоящий перерыв (шаг начат, ответа не ждёт, работа оборвалась) записывается как «прервано» с `duration_s`: работа шага от его «начато» до последнего события хода проекта, без ожидания; простой до возобновления в неё не входит. Записи «прервано» старых журналов без `duration_s` читаются как раньше и ничего не прибавляют. Рядом с временем работы `status` показывает время по часам — от первого до последнего события хода проекта; ожидание ответов и перерывы в него входят (подпись «по часам N мин (с ожиданием ответов и перерывами)»). Одна цифра времени для отчёта о прогоне берётся из `status` после записи решения.
- **Кто держит бюджет.** В Claude Code — хук ([ADR-0009](0009-hooks-accelerators.md)). Он отказывает всем инструментам, кроме команд `strateg`, чтения в папке проекта и записи выпуска с пометкой о неполноте: без чтения выпуск не собрать. Поднять лимит при исчерпании решает человек: на `strateg budget set` хук отвечает «спросить человека», а в `claude -p` без человека это отказ. В других средах — обязательство скилла вызывать `budget check` перед платным действием и отказ CLI на ближайшей границе шага. Это слабее, и так и написано в отчёте о прогоне.
- **Отчёт о прогоне** собирает время, стоимость по шагам и по ролям, а для каждой роли — модель, токены, число вызовов и повышения модели. Ещё в нём повторы, сбои, ожидание ответа на воротах и правки человека.

## Последствия
- Проще: руководитель и проверяющий видят цену результата, её точность и долю каждой роли.
- Сложнее: таблицу цен надо держать с датой обращения; разбор транскриптов зависит от их формата. Токенайзер моделей 4.7 и новее даёт больше токенов на тот же текст: на учёт по транскриптам это не влияет, но бюджет по умолчанию считается по замеру первого прогона, а не по старым оценкам.
- Нужно сделать: разбор транскриптов основного агента и субагентов; хуки `SubagentStop`, `Stop` и проверка в `PreToolUse`; `prices.yaml` по моделям с абсолютными ценами, ценой кэша и порогом длины промпта; `defaults.yaml`; `budget check`; шаблон отчёта о прогоне с разбивкой по ролям; проверка строки статуса в VS Code.

## Польза и замер
- Какую пользу ждём: известна стоимость каждого проекта и каждой роли; в Claude Code бюджет останавливает работу посреди хода без участия модели.
- Как замеряем: на стенде — расхождение оценки по транскриптам с `total_cost_usd` того же прогона: так проверяется способ, которым считается интерактивная работа. Сценарий С-13, прогон б, — на каком шаге и с каким перерасходом остановился автопилот.
- Результат замера сквозного прогона: см. «Точность веб-поиска и сверка» выше; время работы в нём было занижено на треть из-за трёх «прервано» без длительности (16,5 мин при 25,3 мин без потерь), стоимость — на 4,7 % из-за веб-поиска.
- Результат замера: 08.11.2026, один малый прогон `claude -p` (основной агент на Haiku 5.5, критик на Sonnet 5.5) — оценка по транскриптам совпала с `total_cost_usd`, расхождение 0,00 %, токены совпали по каждой модели. Веб-поиск, длинный промпт Haiku, быстрый режим и регион США проверены только тестами; замер на нескольких прогонах — на стенде.
- Если пользы нет или не успеваем: хранится только итог проекта по транскриптам, без разбивки по шагам; бюджет — только по времени.

## Изменения
- 10.11.2026: событие «ответ человека» (хук `UserPromptSubmit`) кончает ожидание после остановки в момент ответа: работа до первой команды CLI больше не вычитается.
- 09.11.2026: веб-поиск входит в оценку стоимости (вызовы `WebSearch` плюс запрос к модели поиска, `web_search_query` в таблице цен); бюджет по умолчанию $8 и 60 минут по замеру сквозного прогона; шаг на воротах и после остановки не прерывается при возобновлении; ожидание после остановки не считается работой; «прервано» получает `duration_s`; `status` показывает время по часам.
- 08.11.2026: по сборке учёта — транскрипт субагента отдельный; роль «служебный» для внутренних агентов среды; бюджет проверяется и перед неплатными вызовами, которые исчерпание закрыло бы; при исчерпании открыто чтение в папке проекта, `budget set` — с вопросом человеку; результат замера; в таблице цен 14 моделей, обращение 08.11.2026.
- 06.11.2026: цены в `prices.yaml` абсолютные, по моделям, с ценой чтения кэша и порогом длины промпта. Множители устаревают при смене тарифа, а у разных моделей кэш стоит по-разному.
