# ADR-0008: Маршрутизация — таблица в config, исправление ошибочного выбора

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | ДУ-1, ТР-3, КО-2; [ADR-0007](0007-subagents.md), [ADR-0010](0010-cost-budget.md) |

## Контекст
Задание ценит выбор процесса, модели и инструмента по задаче, качеству и стоимости — с исправлением ошибочного выбора. Приветствуются специализированные модели, которые выбирают из вариантов, классифицируют или оценивают. По цене API ввод Haiku, Sonnet и Opus соотносится как 1 : 20 : 40 ([цены](https://platform.claude.com/docs/en/about-claude/pricing), обращение 04.11.2026). Дешёвый классификатор окупается, только если его точность измерена. Маршрутизатор «сильная — слабая модель» на бенчмарках экономит больше чем вдвое при малой потере качества ([RouteLLM](https://arxiv.org/pdf/2406.18665)), но не на нашей задаче. Главную работу — варианты и стратегии — ведёт модель, которую пользователь выбрал в среде, и таблица её не меняет. Модель «Jev» из задания — внешний сервис; его доступ и точность не проверены.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Одна модель на всё | Просто | Дорого на рутине или слабо на анализе |
| Таблица правил: вид задачи → модель, effort, инструмент; повышение при провале | Прозрачно, проверяемо, дёшево | Правила надо подобрать |
| Обученный маршрутизатор | Тонко | Нет данных и времени на обучение |

## Решение
`config/routing.yaml` — единственный источник выбора модели для ролей. Таблица: вид задачи → уровень модели (сильная, средняя, дешёвая), effort, инструмент, условие повышения. По умолчанию:
- исследователь — средняя; глубина — число источников на вопрос плана;
- классификатор — дешёвая; ответ «не уверен» — повтор на средней;
- критик — средняя; проверка полноты, проваленная после доработки, — один повтор на сильной;
- синтетический респондент — средняя;
- основной агент — модель, выбранная в среде. Таблица только советует сменить её, если задача требует.

Уровни отображаются на Haiku, Sonnet и Opus. В Claude Code модель роли при запуске субагента подставляет хук ([ADR-0009](0009-hooks-accelerators.md)), вне его — скилл, с пометкой «модель роли не гарантирована». В средах без выбора модели действует `inherit`. Фразы «экономнее» и «глубже» переключают профиль: глубину исследователя и модели ролей. Каждый выбор и каждое повышение пишутся в журнал с причиной. Внешний классификатор, например Jev, может заменить роль классификатора, если доступ есть и точность измерена. Зависимостью он не становится.

## Последствия
- Проще: видно, почему выбрана модель; ошибочный выбор исправляется по правилу.
- Сложнее: в других средах выбор модели субагентом не гарантирован.
- Сделано: таблица, команда `strateg route`, запись выбора в журнал, профили, тест «провал полноты → повтор на сильной». Условия повышения CLI проверяет сам: у критика — итог «не пройдено» в `completeness.yaml`, у классификатора — вердикт «не уверен», вынесенный до повышения. Повтор после повышения виден: запись проверки полноты с моделью критика, вердикты с пометкой «после повышения»; `cost report` у каждого повышения называет итог повтора.

## Польза и замер
- Какую пользу ждём: дешёвая проверка цитат на классификаторе и автоматическое исправление ошибочного выбора. Экономию всего прогона не обещаем: её определяет модель, выбранная пользователем.
- Как замеряем: стоимость и точность классификатора против Sonnet ([ADR-0007](0007-subagents.md)); доля повышений и их итог — стала ли проверка полноты проходить после повтора. По остатку лимита — профиль «обычно» против «всё на сильной».
- Результат замера: ожидается; скрипт и выборка — `scripts/eval_classifier.py` и `evals/classifier/pairs.yaml` ([ADR-0007](0007-subagents.md)). Доля повышений и их итог — из `cost report`.
- Если пользы нет: таблица сокращается до условия повышения полноты, роли работают на модели среды.
