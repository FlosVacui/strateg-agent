# ADR-0012: База знаний и поиск — полнотекстовый поиск и связи, без эмбеддингов

| | |
|---|---|
| Статус | принято; доп. уровень в минимальном объёме; при отставании урезается до полнотекстового поиска без связей |
| Дата | 06.11.2026 |
| Кто решил | команда проекта |
| Связано | ДУ-4, ДВ-6, ТР-2, ТР-3; [ADR-0005](0005-claims-quote-check.md) |

## Контекст
Дополнительный уровень ценит поиск по формулировке, смыслу и связям. Ценит и память между сеансами, которая не превращает прежний ответ агента в факт, с исправлением и отзывом устаревших записей. Агент должен ставиться по инструкции на Windows и macOS без тяжёлых зависимостей. Русский язык с падежами плохо ищется точным совпадением слов.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Поиск инструментом среды по файлам | Ничего не ставить | Нет ранжирования, падежи, медленно на многих снимках |
| SQLite FTS5 с токенизатором `trigram` + расширение запроса синонимами силами модели + связи по номерам | Встроено в Python, устойчиво к падежам, без загрузки моделей | Смысловой поиск приблизительный |
| FTS5 с токенизатором `unicode61` и стеммером | Слова как токены | В пробе «абонент» не находит «абонентов»; формы слова из `pymorphy3` как токены это снимают (запасной путь) |
| Эмбеддинги и векторная база | Хороший смысловой поиск | Загрузка модели или платный API, тяжёлая установка |

## Решение
Индекс SQLite FTS5 с триграммами по утверждениям (текст, предмет, цитаты), снимкам источников, материалам, выпущенным документам и методике: `strateg search "<запрос>"`. Триграммы ищут подстроку, а не слово, и различают ё и е: «оттоку» не находит «отток». Поэтому CLI до индекса и до запроса приводит регистр и ё к е (длина текста не меняется: смещения отрывков считаются по исходному тексту, NFKC не применяется). Устойчивость к падежам даёт словарь `pymorphy3`, он уже в зависимостях: для каждого слова запроса берутся все формы слова (лексема), поиск идёт по любой из них. Формы ловят и беглые гласные («рынок» — «рынка»), которые срез окончания не ловит. `snowballstemmer` в зависимостях нет и не добавляется; правило «срез окончания и основа без последней буквы» осталось в коде только для замера (способ `stem`). Запрос короче 3 знаков идёт подстрокой без индекса. Поиск «по смыслу» — модель расширяет запрос синонимами и формулировками, CLI ищет все (`--also`, повторяемый параметр) и объединяет по рангу.

- **Запрос.** Из него берутся только слова (буквы и цифры); кавычки, `*`, `-`, `:`, скобки, `AND`, `OR`, `NOT`, `NEAR` силы не имеют, каждое слово уходит в FTS5 в кавычках. Слова должны встретиться вместе в одном куске текста (500–800 знаков); не нашлись — места с частью слов, и выдача об этом говорит. Слова короче 3 знаков рядом с длинными проверяются подстрокой по найденному куску.
- **Выдача.** Номер (`У-n`, `И-n`, путь файла методики), отрывок одной строкой (до 220 знаков, без управляющих знаков, в `--json` отдельным полем с признаком `untrusted`), смещение в тексте снимка и страница. У утверждения — тип, происхождение, статус, источники и места цитат. Отозванное и заменённое идёт последним и с пометкой («заменено на У-m», «отозвано: причина»), `--only-active` его скрывает. Происхождение «агент» названо «вывод агента, не факт»; «подозрительный» источник и утверждение по нему помечены. Объём ограничен (`--limit`, по умолчанию 8).
- **Связи.** Обход «источник → утверждения → варианты, решения, обязательства, разделы документов» уже делает `strateg impact`; второго обхода нет. `search` показывает у утверждения его источники и места цитат, а в конце выдачи подсказывает `strateg impact <номер>`.
- **Индекс.** Производный файл, его можно удалить. Проект: `.tmp/search.sqlite` (вне архива `pack` и вне `check`; `.tmp/` закрыта исследователю и критику, а в индексе есть материалы человека). Методика: `projects/.cache/knowledge-search.sqlite`, общий для проектов и вне git, по образцу `.cache/fetch.json` у проекта. Пересборка — по хешу входных файлов (реестры, тексты снимков и материалов, документы) и способа поиска; файлы читаются один раз под блокировкой папки, по ним же строится индекс. Запись — атомарная замена файла без блокировки папки; занятый файл (на Windows) индекс не обновляет, а ответ строится из свежего. Удалённый или испорченный файл — тихая пересборка. `search` проект не меняет и событий не пишет.
- **Запасной путь.** Нет `trigram` (SQLite до 3.34 или сборка без него): `unicode61` по приведённому тексту, формы слов — токены. Нет FTS5: перебор в Python. `strateg doctor` показывает версию SQLite и наличие `trigram`.
- **Права.** `search` видит `inputs/`. Правила хука дают исследователю в Bash одну команду, `strateg fetch`, а критику Bash закрыт целиком ([ADR-0011](0011-data-safety.md)): `search` у основного агента, и это проверяет тест зон.

Поиск по связям — ссылки по номерам между источниками, утверждениями, вариантами и решениями ([ADR-0005](0005-claims-quote-check.md)). Память между сеансами — файлы проекта и статусы утверждений. Прежний ответ агента записывается с происхождением «агент» и фактом не становится: модель данных отказывает «факту» с таким происхождением.

## Последствия
- Проще: установка лёгкая; поиск работает офлайн; в новом сеансе агент находит установленное, не читая `claims.yaml` и снимки целиком.
- Сложнее: смысловой поиск хуже, чем на эмбеддингах; это записано в ограничения README. Словарь `pymorphy3` грузится около 0,2 с на каждый запуск `search`.
- Сделано: индекс, пересборка, приведение ё к е и формы слов, проверка SQLite в `doctor`, замер `scripts/eval_search.py`.

## Польза и замер
- Какую пользу ждём: агент находит нужное утверждение или источник быстрее и с меньшим контекстом, чем чтением файлов.
- Как замеряем: 20 запросов по вымышленному проекту (25 источников, 60 утверждений, `tests/search_corpus.py`) с известными ответами; 10 из них в другом падеже или числе, 3 с беглой гласной, 5 с синонимом через `--also`. Доля запросов с верным ответом в первой пятёрке у поиска с триграммами, у `unicode61` и у простого поиска подстроки по файлам; размер выдачи против размера файлов. Запуск: `uv run python scripts/eval_search.py`.
- Результат замера (16.11.2026, SQLite 3.53):

| Способ | В первой пятёрке | В первой тройке | На первом месте | Все слова вместе |
|---|---|---|---|---|
| Триграммы, формы слова (`pymorphy3`) — выбран | 20 из 20 | 20 | 18 | 20 |
| Триграммы, срез окончания (способ первой редакции) | 20 из 20 | 20 | 18 | 19 |
| Триграммы, формы и срез | 20 из 20 | 20 | 18 | 20 |
| Триграммы, без приведения слов | 15 из 20 | 14 | 11 | 8 |
| `unicode61`, формы слова (запасной путь) | 20 из 20 | 20 | 17 | 20 |
| `unicode61`, без приведения слов | 15 из 20 | 14 | 9 | 9 |
| Простой поиск подстроки по файлам | 17 из 20 | 17 | 14 | — |

  Выбраны формы слова. Срез окончания даёт то же в первой пятёрке, но запрос «многоразовых сумок» нашёл только по части слов, а основа без последней буквы, которой он ловит «рынок», даёт трёхзнаковые основы («рын», «кон»): на замере лишнего они не принесли, но на большом проекте совпали бы с чужими словами. Выдача `search` — в среднем 727 знаков: 1,7 % от `claims.yaml` и всех снимков (42 279 знаков) и 2,0 % от файлов с ответом. Время на машине разработки: пустая команда `strateg --version` 0,85 с, первый `search` с построением индекса 1,07 с, повторный 1,00 с; внутри процесса построение индекса 0,09 с, повторный поиск 0,014 с, загрузка `pymorphy3` 0,17 с. Индекс проекта — 148 КБ на 70 КБ текста. Порог в тесте: 18 из 20 в первой пятёрке (факт 20 минус запас 2).
- Оговорка: корпус вымышленный и небольшой, запросы писали разработчики. Перевес над простым поиском в первой пятёрке мал (20 против 17), заметнее на порядке выдачи (MRR 0,94 против 0,78) и на контексте; на большом проекте замер не проводился. `unicode61` с формами слова на этом наборе не хуже триграмм: триграммы остаются главным путём из-за подстрок (составные слова, числа, неизвестные словарю слова).
- Если пользы нет: поиск убираем, агент ищет инструментом среды; связи по номерам остаются.

## Изменения
- 06.11.2026: запрос приводится к ё→е и к основе слова. Триграммы без этого не находят слово в другом падеже, а запасной путь — колонка со стеммированным текстом, не `unicode61`.
- 16.11.2026: вместо основы по `snowballstemmer` (его нет в зависимостях) формы слова из `pymorphy3`: по замеру они находят все слова вместе в 20 запросах из 20 (срез окончания — в 19) и ловят беглые гласные. Запасной путь без `trigram` — `unicode61` по приведённому тексту, формы слов как токены (а не стеммированная колонка); без FTS5 — перебор. Индекс проекта — `.tmp/search.sqlite`, методики — `projects/.cache/knowledge-search.sqlite`. Записан результат замера.
