# ADR-0014: Выходные документы и экспорт

| | |
|---|---|
| Статус | принято; HTML и PDF — доп. уровень |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | ОМ-5.1…ОМ-5.3, УА-4, СД-2, КО-4; [ADR-0005](0005-claims-quote-check.md), [ADR-0010](0010-cost-budget.md) |

## Контекст
Результаты должны быть оформлены ясно и пригодны для принятия решений. Демонстрационный проект сдаётся «в читаемом виде». Руководитель продукта читает документы без инструментов разработчика. Тяжёлые зависимости для экспорта (pandoc, LaTeX) усложняют установку.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Только Markdown | Ничего не ставить | Хуже вид для руководства |
| Markdown — основной формат; HTML по шаблону из Python; PDF печатью HTML | Лёгкая установка, ссылки на утверждения кликабельны | PDF требует браузера |
| pandoc и LaTeX | Красивый PDF | Тяжёлая установка, Windows |

## Решение
Документы пишутся в Markdown по шаблонам из `knowledge/templates/`:
- одна страница для решения;
- отчёт;
- картина ситуации, варианты;
- продуктовая и коммуникационная стратегии, план проверки;
- отчёт о прогоне.

Документы для чтения начинаются с раздела «Кратко». Утверждения в тексте помечены номером и типом. `strateg export html` собирает HTML по шаблону, и номер утверждения в нём ведёт к основанию: цитате, источнику, дате. PDF — печать того же HTML установленным браузером (Chrome или Edge в режиме без окна), если он найден; иначе человек печатает HTML сам. Своего браузера CLI не скачивает. DOCX не делаем.

## Последствия
- Проще: один источник текста, несколько видов.
- Сложнее: шаблоны надо держать в согласии со схемами.
- Нужно сделать: шаблоны, экспорт HTML, проверку «одна страница помещается на страницу A4».

## Польза и замер
- Какую пользу ждём: руководитель за 2–3 минуты понимает рекомендацию; основание любого утверждения находится быстрее, чем в Markdown.
- Как замеряем: проверяющий читает одну страницу и отвечает на 3 вопроса — что рекомендуем, почему, что заставит передумать. Затем находит основание 5 утверждений по номеру в HTML и в Markdown — время на каждое.
- Результат замера: ожидается.
- Если пользы нет: оставляем только Markdown.
