# ADR-0013: MCP — только Playwright для снимков экрана, своего сервера нет

| Связано | ДУ-3, ДВ-3, ТР-2, ТР-5.3; [ADR-0002](0002-cli-single-interface.md), [ADR-0004](0004-sources-snapshots.md), [ADR-0007](0007-subagents.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Дополнительный уровень ценит интеграции через MCP и CLI. Анализ пользовательского опыта должен опираться на то, что видно в материале. Браузер в руках агента — это и недоверенный вход, и внешний канал: он переходит по ссылкам, редиректам и кнопкам, а в ответ на действие по умолчанию возвращает текст страницы ([Playwright MCP](https://github.com/microsoft/playwright-mcp), обращение 05.11.2026). Форматы настроек MCP в средах разные: `.mcp.json`, `.cursor/mcp.json`, `opencode.json` и другие. Программный интерфейс агента уже есть — CLI ([ADR-0002](0002-cli-single-interface.md)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Без MCP | Проще установка | Нет снимков экрана живого интерфейса |
| Готовый Playwright MCP у исследователя: только переход и снимок экрана по адресам, которые дал человек | Реальные снимки; браузер в роли без доступа к чувствительному | Нужен Node и браузер |
| Playwright у основного агента | Проще | Основной агент получает веб — нарушение правила двух |
| Свой MCP-сервер поверх CLI | Красиво для критерия «интеграции» | Дублирует CLI, стоит времени, по-разному настраивается в средах |

## Решение
Playwright MCP подключается только к исследователю и только для разбора интерфейсов:
- адреса для разбора человек даёт сам, `strateg add --ux <адрес>` заносит их в список. В Claude Code эта команда стоит в правиле `ask`: среда показывает адрес и спрашивает человека. На стенде список приходит из карточки кейса. Файл списка правит только CLI;
- хук держит белый список из двух инструментов Playwright: `browser_navigate` и `browser_take_screenshot`. Всё остальное запрещено: клики, ввод, загрузка файлов, `browser_snapshot`, `browser_evaluate`, `browser_run_code_unsafe` ([ADR-0009](0009-hooks-accelerators.md)). Параметр `filename` у снимка запрещён: относительное имя пишется от корня рабочей папки мимо `--output-dir`;
- переход разрешён только на адрес из списка целиком. После перехода хук сверяет итоговый адрес с доменом из списка. Если он ушёл на чужой домен, переход помечается неподтверждённым, и снимок экрана запрещён до нового перехода. Встроенные списки доменов Playwright границей не считаем: по документации они не действуют на редиректы;
- версия `@playwright/mcp` зафиксирована, не `@latest`: пакет зависит от предрелизной сборки Playwright. Браузер: `--browser msedge` на Windows, `chrome` на macOS;
- в настройках сервера `--snapshot-mode none`: текст страницы в ответах на действия не идёт. Это верно только вместе с белым списком: `browser_snapshot` и `browser_evaluate` при этом режиме остаются и вернули бы страницу сами;
- снимки экрана Playwright пишет во временную папку `--output-dir`: она исключена из git и лежит вне папки проекта. Исследователь передаёт путь файла, основной агент регистрирует его командой `strateg add`, и CLI кладёт снимок в `sources/`. Исследователь видит снимок при съёмке; на персональные данные снимок кодом не проверить — это публичный экран по адресу, который подтвердил человек, и так записано в ограничения;
- замечания по интерфейсу ссылаются на снимки;
- текст страниц через Playwright как источник не берётся, для этого есть `strateg fetch` ([ADR-0004](0004-sources-snapshots.md)).

Настройки для сред генерирует скрипт из одного описания. Своего MCP-сервера нет и не будет: он дублировал бы CLI. Интеграция через MCP — это Playwright, интеграция через CLI — `strateg`. Если Node не установлен, разбор интерфейсов идёт по снимкам экрана, которые дал человек.

## Последствия
- Проще: интеграции — CLI и один проверенный MCP с узким применением в одной роли.
- Сложнее: для снимков нужен Node; `doctor` проверяет его наличие и предупреждает, если версия ниже 22 (пакет требует 18 и новее, но Node 18 снят с поддержки), но это не ошибка.
- Нужно сделать: список адресов разбора в CLI; правила хука для инструментов Playwright (белый список, запрет `filename`); описание сервера и генерация настроек для Claude Code, Cursor и OpenCode.

## Польза и замер
- Какую пользу ждём: замечания по интерфейсу ссылаются на видимые элементы реальных экранов.
- Как замеряем: сценарий С-8 — доля замечаний с указанием экрана и элемента; сравнение с разбором по описанию без снимков; тест «адрес из списка редиректит на чужой домен».
- Результат замера: ожидается.
- Если пользы нет: Playwright убираем, разбор — только по снимкам человека.
