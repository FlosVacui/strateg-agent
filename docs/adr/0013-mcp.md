# ADR-0013: MCP — только Playwright для снимков экрана, своего сервера нет

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | ДУ-3, ДВ-3, ТР-2, ТР-5.3; [ADR-0002](0002-cli-single-interface.md), [ADR-0004](0004-sources-snapshots.md), [ADR-0009](0009-hooks-accelerators.md) |

## Контекст
Дополнительный уровень ценит интеграции через MCP и CLI. Анализ пользовательского опыта должен опираться на то, что видно в материале. Браузер в руках агента — это и недоверенный вход, и внешний канал: он может перейти по любому адресу и заполнить форму. Форматы настроек MCP в средах разные: `.mcp.json`, `.cursor/mcp.json`, `opencode.json` и другие. Программный интерфейс агента уже есть — CLI ([ADR-0002](0002-cli-single-interface.md)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Без MCP | Проще установка | Нет снимков экрана живого интерфейса |
| Готовый Playwright MCP только для снимков экрана по адресам, которые дал человек | Реальные снимки, известный инструмент, узкое применение | Нужен Node и браузер |
| Playwright и для чтения страниц на JS | Больше сайтов | Текст страниц идёт мимо снимков и проверок CLI |
| Свой MCP-сервер поверх CLI | Красиво для критерия «интеграции» | Дублирует CLI, стоит времени, по-разному настраивается в средах |

## Решение
Подключаем готовый Playwright MCP только для разбора интерфейсов (доп. уровень). Адреса для разбора человек даёт сам: `strateg add --ux <адрес>` заносит их в список. В Claude Code хук пропускает переходы только по адресам из списка ([ADR-0009](0009-hooks-accelerators.md)). Снимки экрана регистрируются как источники через `strateg add`, и замечания по интерфейсу ссылаются на них. Текст страниц через Playwright как источник не берётся: для этого есть `strateg fetch` ([ADR-0004](0004-sources-snapshots.md)). Настройки для сред генерирует скрипт из одного описания. Своего MCP-сервера нет: если останется время, это тонкая обёртка над CLI, и она первая в списке урезания. Если Node не установлен, разбор интерфейсов идёт по снимкам экрана, которые дал человек.

## Последствия
- Проще: интеграции — CLI и один проверенный MCP с узким применением.
- Сложнее: для снимков нужен Node; `doctor` проверяет его наличие, но это не ошибка.
- Нужно сделать: список адресов разбора в CLI, описание сервера и генерация настроек для Claude Code, Cursor и OpenCode.

## Польза и замер
- Какую пользу ждём: замечания по интерфейсу ссылаются на видимые элементы реальных экранов.
- Как замеряем: сценарий С-8 — доля замечаний с указанием экрана и элемента; сравнение с разбором по описанию без снимков.
- Результат замера: ожидается.
- Если пользы нет: Playwright убираем, разбор — только по снимкам человека.
