# ADR-0015: Оценка и сравнение с исходным способом

| | |
|---|---|
| Статус | принято |
| Дата | 05.11.2026 |
| Кто решил | команда проекта |
| Связано | ДУ-7, КО-2, КО-3, КО-4; все ADR — раздел «Польза и замер» |

## Контекст
Дополнительный уровень ценит измерение того, насколько агент быстрее, дешевле или точнее аналитика вручную или обычного чата и какой ценой. Каждый компонент должен оправдать свою сложность пользой, а для этого нужен замер. Лимиты подписок и сроки не дают прогнать всё. Что известно о стенде и оценке (обращение 04.11.2026):
- `claude -p` подходит для автотестов ([headless](https://code.claude.com/docs/en/headless)):
  - `--bare` требует API-ключ и не грузит проект; без него грузятся хуки и `.mcp.json` проекта без диалога доверия;
  - режим прав по умолчанию в `-p` отказывает в любом запросе разрешения;
  - при `--resume` итог стоимости накопительный, `usage` не включает субагентов, а `modelUsage` включает;
- у LLM-судей есть искажения — позиционное, многословие, самопредпочтение; их снижают попарное сравнение с обменом позиций, рубрика и калибровка по ручной разметке ([MT-Bench](https://arxiv.org/abs/2306.05685), [CALM](https://arxiv.org/abs/2410.02736)).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Оценка «на глаз» по демо | Дёшево | Не доказательство |
| Стенд `claude -p` с синтетическим руководителем на воротах; сравнение с обычным чатом и аналитиком; обязательные и необязательные замеры | Числа для README и описания работы | Стоит лимита; судья одной семьи моделей |

## Решение
**Стенд** в `evals/`:
- **Прогон агента.** Ворота — это конец вызова `claude -p`. Синтетический руководитель отвечает по карточке кейса, и прогон продолжается через `--resume`. Права задаются явно: `--permission-mode` и `--allowedTools` для команд `strateg`. Предохранители — `--max-budget-usd` и `--max-turns`.
- **Стоимость** — последнее накопительное значение `total_cost_usd` и `modelUsage`, без суммирования по вызовам.
- **Сравнение.** Обычный чат той же модели с тем же запросом и материалами. На одном кейсе — аналитик вручную, до 4 часов, с таймером.
- **Минуты человека** синтетический руководитель не даёт. Их даёт отдельный прогон одного кейса с живым человеком в пилоте; там же записываются поправки на воротах ([ADR-0006](0006-workflow-gates-modes.md)).
- **Глубина** — попарно и вслепую с обменом позиций; победа засчитывается только в обоих порядках. **Калибровка судьи** — по ручной разметке 20–50 примеров. Ограничение «судья из той же семьи моделей» записано в результатах.

**Замеры:**

| Замер | Когда | Цена |
|---|---|---|
| Агент против обычного чата на 3 кейсах, один не из телекома | обязательно | 6 прогонов |
| Новый кейс, которого команда не видела | обязательно | 1 прогон |
| Живой человек в пилоте на одном кейсе | обязательно | 1 прогон и время человека |
| Классификатор против ручной разметки и Sonnet | обязательно | без полных прогонов |
| Искажённые цитаты против нечёткого совпадения | обязательно | без модели |
| Аналитик вручную на одном кейсе | обязательно | до 4 часов человека |
| Абляции: без критика, без исследователя | по остатку лимита | по 1–3 прогона |
| Маршрутизация: «обычно» против «всё на сильной» | по остатку лимита | 1–3 прогона |
| Поиск: триграммы против файлов | по остатку лимита | без полных прогонов |
| Раздельный критик против двух режимов | по остатку лимита | 1–3 прогона |

При отставании остаются только обязательные замеры, из абляций — только классификатор. Итоги — в `docs/benchmark.md`, кейсы и рубрики — в `evals/`.

## Последствия
- Проще: каждое «Польза и замер» в ADR получает число или явную пометку «не измерено».
- Сложнее: прогоны тратят лимит; их число задаётся по стоимости первого прогона.
- Нужно сделать: карточки кейсов, синтетический руководитель, рубрика, протокол судьи, `docs/benchmark.md`.

## Польза и замер
- Какую пользу ждём: доказательство пользы агента и его частей вместо утверждений.
- Как замеряем: сам стенд; согласие судьи с ручной разметкой.
- Результат замера: ожидается.
- Если пользы нет: если стенд слишком дорог, прогонов меньше, а сравнения делаются вручную по тому же протоколу и с той же рубрикой.
