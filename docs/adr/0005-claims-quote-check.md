# ADR-0005: Реестр утверждений, проверка цитат и связи для пересчёта

| Дата | 06.11.2026 |

## Контекст
Критерий «Проработанность» требует связи выводов с проверяемыми источниками и отделения фактов от гипотез и прогнозов. Память агента не должна превращать прежний ответ в факт, устаревшие записи нужно исправлять и отзывать. Атаки на память агентов работают через обычные запросы ([MINJA](https://arxiv.org/abs/2503.03704)). Поэтому важны происхождение записи и статус, а не подпись. При уточнении рамки, исправлении и новых данных нужно найти, что затронуто и какие ворота с ответом человека это задевает.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Ссылки в тексте отчёта | Просто | Не проверить машинно, не найти затронутое |
| Реестр утверждений с типом, происхождением, цитатами и статусом; проверка цитаты кодом; связи по номерам | Проверяемо; пересмотр по связям | Нужна дисциплина записи через CLI |
| Проверка цитат моделью-судьёй | Понимает перефразы | Дорого, ошибается, не повторяемо |

## Решение
**Утверждение** `У-n` — текст, тип, происхождение (источник, пользователь, агент, синтетика), основания, предмет, период, регион, поля источника (ниже), статус (действует, заменено, отозвано), ссылки «заменяет» и «заменено на», ссылки на утверждения-основания и на вопрос плана. Правила держит CLI:
- **факт** — хотя бы одна цитата из источника, который не синтетика, найденная в снимке, с местом (`locator`);
- **гипотеза** — основания и способ проверки; **прогноз** — основания и диапазон; **допущение** — откуда взято;
- правка пользователя без источника — допущение с происхождением «пользователь»;
- «заменено» — только если у нового утверждения те же предмет, период и регион. Эти поля заполняет агент, совпадение проверяет CLI. Иначе оба утверждения остаются, а расхождение идёт в картину;
- отзыв — новая запись статуса, старая не стирается.

**Поля источника.** Исследователь передаёт с каждым утверждением издателя первоисточника, вид источника и признак «о себе» — источник пишет о себе или своём продукте. Вид — из закрытого списка: официальный первоисточник, отраслевое исследование, СМИ, вторичный пересказ, отзыв пользователя, материал пользователя. CLI добавляет «подозрительный» ([ADR-0011](0011-data-safety.md)) и считает «независимых первоисточников»: перепечатка и пересказ одного первоисточника — один первоисточник. Поле «спор» — ссылка на утверждение с расхождением и причина. Вычисляемых уровней «надёжность» и «достоверность» нет, числовую «уверенность» модель не ставит: картина показывает исходные поля, и по ним видно, на чём держится вывод. Спорящие источники не усредняются: в картине остаётся пара утверждений и причина расхождения.

**Проверка цитаты** идёт в два слоя. Первый — код: нормализация (NFKC, ё и е, кавычки, тире, мягкие переносы, пробелы, регистр), затем точное вхождение в снимок, затем вид без пробелов и дефисов, затем нечёткое совпадение по окну (rapidfuzz, `partial_ratio_alignment`) с порогом. **В найденном окне числа и отрицания должны совпасть**, иначе цитата не проходит: одного порога мало, на пробе подмена цифры даёт сходство 98,2 %, вставка «не» — 95,0 %. Цитата короче 40 знаков проходит только точным вхождением. `token_set_ratio` не используется. Стартовый порог — 93, он подбирается на 50 размеченных парах так, чтобы искажённые цитаты не проходили. Второй слой — подтверждает ли цитата утверждение по смыслу. Это решает классификатор ([ADR-0007](0007-subagents.md)), и только для фактов, которые идут в рекомендацию.

**Связи для пересчёта.** Узлы: рамка → вопрос плана → источник → утверждение → вариант → раздел стратегии → решение. Каждый узел знает свой шаг, а шаг — свои ворота. `strateg affected` возвращает затронутые узлы и ворота, на которых человек уже ответил. По этому списку скилл решает, пересчитывать сразу или после подтверждения.

## Последствия
- Проще: жюри проверяет любое сведение за два шага; пересмотр находит затронутое без перечитывания всего.
- Сложнее: скиллы обязаны записывать утверждения через CLI; цитаты из PDF требуют нормализации переносов.
- Нужно сделать: схемы, команды `claim`, `quote check`, `affected`, отрицательные тесты — факт без цитаты, факт из синтетики, «заменено» при другом периоде, цитата с подменённой цифрой, цитата с вставленным «не», короткая цитата с опечаткой; подсчёт независимых первоисточников.

## Польза и замер
- Какую пользу ждём: факты рекомендации подтверждаются источником по смыслу; искажённые цитаты не проходят; пересмотр находит ожидаемый набор затронутого.
- Как замеряем: ручная сверка 30–50 фактов — доля, где цитата подтверждает утверждение; доля искажённых цитат (подменено число, слово, отрицание), которые прошли нечёткое совпадение; сценарий С-5 с заранее известной цепочкой — полнота и точность `affected`.
- Результат замера: ожидается.
- Если пользы нет или не успеваем: по частям. Без нечёткого совпадения — только точное после нормализации. Без `affected` — связи остаются в файлах, и затронутое по ним ищет скилл. Реестр с правилами типов остаётся всегда: это основа критерия «Проработанность».

## Изменения
- 06.11.2026: к проверке цитаты добавлена сверка чисел и отрицаний, а к утверждению — поля источника (издатель, вид, «о себе», «подозрительный», число независимых первоисточников, спор). Порог сходства не ловит подмену цифры и «не», а без этих полей не видно, на чём держится вывод.
