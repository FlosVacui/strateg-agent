# Матрица требований и доказательств

Каждое требование задания МегаФона «Стратег Фабрики проектов» получает ID. По каждому указано, чем оно закрыто и где доказательство: файл, тест, замер, минута видео, раздел описания работы. Матрица обновляется при приёмке каждого пакета работ и входит в описание работы. Проверочные сценарии С-1…С-14 и их связь с ID — в [пути пользователя](user-journey.md#связь-с-требованиями), решения по требованиям — в [архитектуре](architecture.md#10-связь-с-требованиями).

**Статусы:** план — ещё не сделано; частично — сделана основа, доказательство есть, требование закрыто не целиком; сделано — реализовано, доказательство есть; проверено — доказательство подтверждено независимым прогоном или ревью.

**Сквозной прогон** в доказательствах — прогон 08.11.2026: Claude Code `claude -p`, основная модель Sonnet 5.5, субагенты `researcher` и `critic`, хуки включены. Задача руководителя продукта — стоит ли оператору связи держать подписку на несколько онлайн-кинотеатров и что говорить аудитории. Пройдены все восемь шагов, выпуск — с пометкой о неполноте: бюджета по умолчанию не хватило на повторную проверку полноты. Проект прогона в репозиторий не входит: в нём снимки чужих страниц целиком. Числа прогона войдут в `docs/benchmark.md`. «Проверено» ставится после повторов на стенде.

**Повторный прогон** — 15.11.2026, тот же вопрос и та же среда, основная модель Sonnet 5.5, продукт с исправлениями этапа 4: три сессии, новая сессия без `--resume`, документ человека в `inputs/`, после выпуска — новые данные. **Живые проверки 18–19.11.2026** — Claude Code `claude -p`, основная модель Opus 5.5, хуки включены; проект — копия образца или учебный кейс. **Прогон стенда 19.11.2026** — `evals/run.py`: изолированная копия продукта, синтетический руководитель отвечает на ворота по карточке учебного кейса «Защита от мошенников», бюджет $8.

## Как устроен агент
| ID | Требование | Чем закрыто | Доказательство | Статус |
|---|---|---|---|---|
| УА-1 | Рабочий процесс: агент сам ведёт шаги от запроса до стратегии и подключает человека при существенном выборе | `AGENTS.md` («Путь», «Внеплановые остановки»), скилл `strateg`, команды `step`, `gate`, `mode`, `stop`, режимы «пилот» и «автопилот»; в автопилоте после ответа на ворота или остановку агент идёт дальше без вопроса «продолжить?»; шаг 8 после выпуска останавливается командой `stop`, а не ждёт в чате | `tests/test_end_to_end.py`; `tests/test_skills.py` (автопилот идёт дальше после ответа на ворота и остановку, шаг 8 останавливается, `diff` перед закрытием шага 8, `--by пользователь` только для названного человеком). Сквозной прогон: восемь шагов, человек — на В1 и В4 и на остановке по бюджету с тремя ответами. Бюджета по умолчанию не хватило на повторную проверку полноты. Повторный прогон 15.11.2026: выпуск снова с пометкой «Неполно» (часть Б проверки полноты — десять пунктов «нет»). Живая проверка 18–19.11.2026 в Claude Code: в автопилоте «продолжить?» ни разу; две остановки, обе по правилам; на шаге 8 ссылка не открылась — `stop` с вопросом. В прогоне стенда 19.11.2026 агент остановился по бюджету словами при остатке $0,35: проверка бюджета не знала цены шага; правка есть (`budget check --next`), повторно вживую не проверена. Во втором прогоне стенда 20.11.2026 повтор проверки полноты израсходовал весь бюджет ($8,61 из $8), и выпуск не записан | частично |
| УА-2 | Порядок в знаниях: инструкции, методические знания, материалы проекта и состояние задачи хранятся раздельно | `AGENTS.md` и скиллы / `knowledge/` / `projects/<id>/inputs`, `sources`, `outputs` / `state.yaml`, `journal.jsonl`, `history/`; зоны прав ролей в хуке `PreToolUse` | [Модель данных](data-model.md), схемы `schemas/`, `tests/test_project_check.py`, `tests/test_output_files.py`, `tests/test_hooks_rules_zones.py`. Сквозной прогон: проект разложен по слоям, прежние версии — в `history/`, хук не пустил критика в `inputs/`, `.tmp/` и `history/` | сделано |
| УА-3 | Продолжение после перерыва, в том числе в новом чате; продолжение с копии проекта-примера | `state.yaml`, журнал, `strateg status --brief`, хук `SessionStart`, скилл `strateg`; `strateg new <номер> --from example` копирует пример целиком под новым номером, источник не меняется, время и стоимость считаются от копии | `tests/test_status_brief.py`, `tests/test_hooks_integration.py`; параллельные команды не теряют записей — `tests/test_parallel_write.py`, `tests/test_lost_records.py`; копия примера — `tests/test_project_copy.py` (источник не меняется ни на байт, копия проходит `check`, сбой посреди копирования не оставляет полпапки). Сквозной прогон: продолжение в новой сессии без «прервано» на воротах и остановках, сопровождение после выпуска в новой сессии. Повторный прогон 15.11.2026: новая сессия без `--resume` приняла ответ на В4 и пошла дальше. Не проверено: самого проекта-примера в репозитории пока нет, копия проверена на образцах из тестов; вживую `new --from example` не запускалась | частично |

Сквозной прогон: каждый факт ведёт к снимку и цитате, стоимость — по ролям и шагам. Веб-поиск входит в оценку стоимости (`tests/test_transcript.py`, `tests/test_cost_report.py`); время работы считается без ожидания ответа человека на воротах и после остановки (`tests/test_time_pause.py`). Стоимость — оценка по транскриптам и таблице цен | частично |
