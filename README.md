# «Стратег» — ИИ-агент для руководителя цифрового продукта

> Статус: в разработке. Хакатон МегаФона «Стратег Фабрики проектов», сдача — 22.11.2026.

«Стратег» — это папка-проект для Claude Code, Cursor, OpenCode и других сред с ИИ-агентами. Руководитель продукта пишет запрос своими словами, а агент ведёт его по шагам:

1. **Постановка** — уточняет вопрос, цель, получателя результата, ограничения и данные; спрашивает только то, что важно для следующего шага.
2. **Исследование** — план от вопросов, которые могут изменить решение; источники со ссылками и проверенными цитатами; честный список пробелов.
3. **Варианты** — не меньше четырёх: «оставить как есть», «закрыть направление» и хотя бы два активных, с сильными возражениями; факты отделены от гипотез и прогнозов.
4. **Стратегия** — согласованные продуктовая и коммуникационная стратегии и план проверки.
5. **После решения** — ответственные, показатели, условия пересмотра; пересмотр выводов при новых данных.

Работу можно остановить в любой момент и продолжить в новом чате с того же места. Видно, что агент сделал, на каких основаниях и сколько это стоило.

## Быстрый старт
Нужны только [uv](https://docs.astral.sh/uv/) и Claude Code. Python 3.12 uv поставит сам. После установки uv откройте новое окно терминала.

**1. Установите uv**

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS (Терминал):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**2. Получите проект.** Склонируйте репозиторий (`git clone <адрес репозитория>`) или распакуйте архив с проектом и перейдите в папку:

```bash
cd strateg-agent
```

**3. Поставьте зависимости и проверьте среду** (одинаково на Windows и macOS):

```bash
uv sync
uv run strateg doctor
```

`doctor` покажет, всё ли готово. «OK» — порядок; «ПРЕД» — предупреждение, работать можно (в Windows при предупреждении о кодировке выполните `chcp 65001` или откройте Windows Terminal); «НЕТ» — нужно исправить.

**4. Откройте папку в Claude Code:** выполните `claude` в этой папке или откройте её в VS Code с расширением Claude Code.

**5. Напишите задачу своими словами**, например: «Как продавать подписку на онлайн-курс и что обещать студентам?». Агент заведёт проект, покажет черновик рамки и спросит только открытое. В Claude Code можно начать с команды `/strateg`.

## Команды
Всё, что меняет состояние проекта, делает CLI `uv run strateg …`. Сообщения по-русски, у команд с выводом есть `--json`. Активный проект — файл `projects/.active`; переменная `STRATEG_PROJECT` и флаг `--project` главнее. Коды возврата: 0 — успех, 1 — ошибка данных или правил, 2 — ошибка использования.

| Команда | Что делает |
|---|---|
| `strateg new <id> [--mode автопилот\|пилот] [--region <код>]` | Создаёт `projects/<id>/` и делает проект активным |
| `strateg use <id>` | Выбирает активный проект |
| `strateg status [--json \| --line \| --brief [--peek]]` | Состояние: шаг, ворота, источники, утверждения, время, стоимость, следующее действие; `--line` — одна строка статуса; `--brief` — сводка «где остановились» не больше 10 строк: проект, режим, шаг, ворота, ждущие ответа, следующее действие, прерванные действия, файлы, изменённые вне агента, какие файлы выхода есть. Обычный `--brief` — для нового сеанса: пишет «прервано» (начатое и не завершённое действие, один раз). `--brief --peek` — та же сводка без записи событий: для середины сеанса, например после сжатия контекста, идущий шаг прерванным не становится. «Изменено вне агента» (хеш файла не совпал с `state.yaml`, файл удалён или файл выхода положен рукой) пишет первая команда, которая сохраняет состояние, — по одному событию на файл и изменение; сводка называет такие файлы |
| `strateg step start <шаг>` / `strateg step done <шаг> [--next "<текст>"]` / `strateg step fail <шаг> --reason "<текст>"` | Начало, конец и ошибка шага; повторный `start` без `done` пишет «прервано», после `fail` шаг начинают заново |
| `strateg gate open <В1..В5> --questions <N>` / `strateg gate answer <В1..В5> --answer "<текст>"` | Ворота: открыть и записать ответ человека; ответ на В1 копирует текущую рамку в событие, рамки нет — отказ с подсказкой `strateg write` |
| `strateg mode <автопилот\|пилот>` / `strateg stop --reason "<текст>"` | Смена режима; внеплановая остановка в журнале |
| `strateg fetch <адрес> [--region <код>]` | Снимок страницы или PDF в `sources/`; соблюдает `robots.txt`, не заходит в локальную сеть; если в извлечённом тексте потерялись цены, берёт весь видимый текст; повтор отдаёт сохранённый снимок |
| `strateg add <путь> [--kind <вид>]` | Регистрирует материал из `inputs/` как источник `И-n` с `path`, `text_path` и sha256. Вид по расширению: `.txt`, `.md` — «заметка пользователя»; `.pdf` — «PDF» (метки `[стр. N]`); `.docx` — «документ» (`[абз. N]`, `[таблица N]`, колонтитулы); `.xlsx`, `.csv` — «таблица» (лист и адрес ячейки, например `B2:`); `.pptx` — «презентация» (`[слайд N]`); изображения — «изображение» без текста; `--kind интервью` — расшифровка (`[строка N]`). До модели ищет персональные данные: почту, телефоны, ИНН человека, СНИЛС, номера карт (номера 8-800 и ИНН организации не трогает). Нашёл — обезличенная копия `inputs/i-<n>.txt`, список замен (строка и метка, без значений), исходник уходит из `inputs/` в `.tmp/` проекта и в работу не идёт: цитировать такой материал нельзя, `check` и `pack` ругаются. Персональные данные в имени файла (телефон, почта, номер) считаются персональными данными: материал уходит так же, как при находке в тексте, под нейтральным именем и с категорией «имя файла»; изображение с такими данными в имени — отказ «переименуйте файл». Имена людей — только предупреждение. Закрытые данные и обращения к ИИ — те же признаки и события, что у `fetch`. Повтор того же файла (sha256) отдаёт прежний `И-n`. Аудио и видео — отказ с просьбой дать расшифровку текстом |
| `strateg add --confirm <И-n>` | Человек подтвердил замены: исходник уходит в `~/.strateg/private/<проект>/<И-n>/` вне проекта и архива, в `inputs/` остаётся обезличенная копия. Для изображения — подтверждение, что на нём нет персональных данных |
| `strateg source confirm <И-n>` | Человек подтвердил, что материал с признаками закрытых данных общедоступный: до этого цитировать его нельзя |
| `strateg claim add --file <путь\|->` | Записывает утверждение или список из YAML или JSON; цитата проверяется по снимку, без проверенной цитаты факт не записывается (у факта цитата не короче 3 слов и 20 знаков, все числа утверждения есть в цитатах) |
| `strateg claim replace <У-n> --file <путь\|-> [--by агент\|пользователь]` | Новое утверждение вместо действующего (те же проверки, что у `claim add`): связи `replaces` и `replaced_by`, статус «заменено» и строка истории у прежнего; предмет, период и регион сохраняются, иначе откат. Повтор отдаёт уже записанный номер. Места использования заменённого утверждения (варианты, обещания, строки плана) выводятся: их переписывает `write` |
| `strateg claim revoke <У-n> --reason "<текст>" [--by агент\|пользователь]` | Статус «отозвано», причина в истории статусов; повтор — «уже отозвано», код 0. Отзыв проходит всегда, места использования выводятся |
| `strateg claim list [--type <тип>] [--step <шаг>] [--plan-question <ВП-n>] [--status <статус>] [--json]` | Список утверждений; по шагу и вопросу плана скилл после перерыва получает уже записанное и дописывает недостающее |
| `strateg write --file <путь\|-> [--by агент\|пользователь]` | Записывает файлы выхода одной транзакцией. Вход — YAML или JSON: ключи `frame`, `plan`, `gaps`, `options`, `promises`, `verification`, `decisions`, значение — содержимое файла без `schema_version` (у рамки без `version`). Вход проверяется моделью до записи; если после записи в проекте появились новые ошибки, все файлы, журнал и `history/` возвращаются, а выводятся только новые ошибки (прежние — предупреждение с числом). Те же данные — «без изменений», код 0. Перезапись кладёт прежний файл в `history/<имя>.v<N>.yaml`. Рамка до ответа на В1 — черновик (перезапись на месте), после ответа каждая правка — новая версия. Файлы, которые ссылаются друг на друга (`gaps` и `options`), пишите одним входом |
| `strateg event error --message "<текст>" [--step <шаг>] [--tool <имя>]` | Событие «ошибка» в журнале — из скилла или хука |
| `strateg check` | Проверяет активный проект; при ошибках код 1 |
| `strateg cost add --session <id> --role <роль> --model <модель> [--usd <число> [--source оценка\|измерено]] [--input N --output N --cache-read N --cache-write-5m N --cache-write-1h N] [--total]` | Запись стоимости |
| `strateg budget set [--usd <число>] [--minutes <число>]` | Бюджет проекта в `state.yaml`: лимит денег и времени работы агента. Новый проект получает бюджет из `config/defaults.yaml` (5 долларов и 60 минут). Смена бюджета — событие «бюджет» в журнале, новый лимит виден в `status --line`; так записывается ответ человека «добавить бюджет» после остановки |
| `strateg budget check [--action <что>]` | Код 0 — действие можно, код 1 — бюджет исчерпан, с причиной: деньги, время или оба. Отказ — событие «бюджет». Время — шаги без ожидания ответа на воротах, плюс идущий шаг; стоимость неизвестна — лимит только по времени. `--action выпуск` берёт резерв на выпуск с пометкой о неполноте. `status` и `status --brief` показывают остаток, `status --line` предупреждает с 80 % |
| `strateg pack [--out <путь>]` | Архив `.zip` папки проекта (по умолчанию `projects/<id>.zip`) без `.tmp/`, кэша `fetch` и временных файлов. До упаковки: `check`, поиск секретов (`sk-ant-`, `sk-`, `ghp_`, `github_pat_`, `AKIA`, `xoxb-`, `xoxp-`, закрытые ключи, `Authorization: Bearer …`, `password=` и `token=` с длинным значением) и проверка, что исходников с персональными данными в папке нет. Найдено — отказ с файлом и строкой, значение не показывается. Если `gitleaks` есть в PATH, `pack` запускает и его; в итоговой строке сказано, чем искали: встроенными шаблонами, `gitleaks` использован, не найден или не отработал |

Утверждения и файлы выхода передавайте файлом (лучше в `projects/<id>/.tmp/`, эта папка вне проверок) или через стандартный ввод в UTF-8: длинные русские тексты в аргументах командной строки ломаются. Флаг `--by пользователь` у `write`, `claim replace` и `claim revoke` — правка человека, в журнал идёт ещё и событие «исправление». Шаги `2a`/`2b` и ворота `B1` с латинскими буквами принимаются как `2а`/`2б` и `В1`. `STRATEG_PROJECTS_DIR` переносит папку проектов из `projects/` репозитория в другое место.

Повтор `claim add` с тем же текстом и цитатами возвращает уже записанный номер; если отличаются другие поля (`dispute`, `forecast_range`, `locator` и прочие), команда отказывает: записанное в этой версии не исправляется, запишите новое утверждение. При повторе `cost add` после сбоя передавайте тот же `--message-id`, иначе расход удвоится.

### Ограничения `add` и проверки цитаты
- Детектор персональных данных ловит не всё (ADR-0011). Не находятся ИНН, записанный с пробелами по группам (`500 100 732 259`), и телефон из десяти цифр без `+7`, `8` и `7` (`9161234567`). Номер карты без разделителей заменяется, только если начинается с цифры от 2 до 6.
- У DOCX читаются абзацы, таблицы и колонтитулы. Надписи (текстовые рамки), сноски, комментарии и свойства файла (автор) не читаются и не проверяются: такой файл с персональными данными в них остаётся в `inputs/` как чистый.
- В заметке `.txt` или `.md` блок — строка. Если автор жёстко переносит строки (почта, markdown на 80 знаков), отрицание на следующей строке не видно: цитата, оборванная перед «не», пройдёт. В PDF строки внутри предложения склеиваются, там этого нет.

### Ограничения `fetch`
- Скрытое встроенным стилем (`display:none`, `visibility:hidden`, `font-size:0`, `opacity:0`) и атрибутами `hidden` и `aria-hidden` в снимок не попадает. Скрытое CSS-классами и внешними стилями без отрисовки страницы не поймать.
- Страницы, которые строятся скриптом, дают «нужен браузер»: сохраните страницу вручную в `inputs/`.
- `fetch` не использует системный прокси: за корпоративным прокси страница не откроется.

## Устройство
| Папка | Что там |
|---|---|
| `AGENTS.md`, `CLAUDE.md` | Постоянные инструкции агента |
| `.claude/skills/`, `.claude/agents/` | Скиллы (шаги работы) и субагенты |
| `knowledge/` | Методические знания: карточки методов, шаблоны, рубрики |
| `projects/` | Проекты пользователя: материалы, источники, состояние, выводы |
| `src/strateg/` | CLI `strateg`: состояние, журнал, источники, проверка цитат, затраты |
| `config/` | Настройки: бюджет по умолчанию, цены моделей (позже — маршрутизация: какая модель и какой инструмент для какой задачи) |
| `evals/` | Стенд оценки и сравнение с исходным способом |
| `docs/` | Матрица требований, архитектура, решения (ADR), замеры |

## Требования
- Python 3.12 через [uv](https://docs.astral.sh/uv/) (uv сам поставит нужный Python).
- Одна из сред: Claude Code (основная), Cursor, OpenCode. Копии скиллов в репозитории нет; для Codex один раз запустите `uv run python scripts/sync_skills.py --dest .agents/skills` — агент в Codex не проверялся. GigaCode не поддерживается.
- Платных сервисов сверх подписки на модель в вашей среде не нужно.
- Сканер секретов `gitleaks` ставить не нужно: `pack` ищет ключи встроенными шаблонами, а если `gitleaks` есть в PATH, запускает и его.
