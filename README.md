# «Стратег» — ИИ-агент для руководителя цифрового продукта

> Статус: в разработке. Хакатон МегаФона «Стратег Фабрики проектов», сдача — 22.11.2026.

«Стратег» — это папка-проект для Claude Code, Cursor, OpenCode и других сред с ИИ-агентами. Руководитель продукта пишет запрос своими словами, а агент ведёт его по шагам:

1. **Постановка** — уточняет вопрос, цель, получателя результата, ограничения и данные; спрашивает только то, что важно для следующего шага.
2. **Исследование** — план от вопросов, которые могут изменить решение; источники со ссылками и проверенными цитатами; честный список пробелов.
3. **Варианты** — не меньше четырёх: «оставить как есть», «закрыть направление» и хотя бы два активных, с сильными возражениями; факты отделены от гипотез и прогнозов.
4. **Стратегия** — согласованные продуктовая и коммуникационная стратегии и план проверки.
5. **После решения** — ответственные, показатели, условия пересмотра; пересмотр выводов при новых данных.

Работу можно остановить в любой момент и продолжить в новом чате с того же места. Видно, что агент сделал, на каких основаниях и сколько это стоило.

## Быстрый старт
Нужны только [uv](https://docs.astral.sh/uv/) и Claude Code. Python 3.12 uv поставит сам. После установки uv откройте новое окно терминала.

**1. Установите uv**

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS (Терминал):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**2. Получите проект.** Склонируйте репозиторий (`git clone <адрес репозитория>`) или распакуйте архив с проектом и перейдите в папку:

```bash
cd strateg-agent
```

**3. Поставьте зависимости и проверьте среду** (одинаково на Windows и macOS):

```bash
uv sync
uv run strateg doctor
```

`doctor` покажет, всё ли готово (в том числе версию SQLite и наличие `gitleaks`). «OK» — порядок; «ПРЕД» — предупреждение, работать можно (в Windows при предупреждении о кодировке выполните `chcp 65001` или откройте Windows Terminal); «НЕТ» — нужно исправить.

**4. Откройте папку в Claude Code:** выполните `claude` в этой папке или откройте её в VS Code с расширением Claude Code.

**5. Напишите задачу своими словами**, например: «Как продавать подписку на онлайн-курс и что обещать студентам?». Агент заведёт проект, покажет черновик рамки и спросит только открытое. В Claude Code можно начать с команды `/strateg`. Скиллы шагов вызываются и явно: `/frame`, `/research`, `/options`, `/strategy`, `/package`; после выпуска — `/follow-up` («что решать сейчас», значения показателей) и `/update` (новые данные, пересмотр).

## Команды
Всё, что меняет состояние проекта, делает CLI `uv run strateg …`. Сообщения по-русски, у команд с выводом есть `--json`. Активный проект — файл `projects/.active`; переменная `STRATEG_PROJECT` и флаг `--project` главнее. Коды возврата: 0 — успех, 1 — ошибка данных или правил, 2 — ошибка использования.

| Команда | Что делает |
|---|---|
| `strateg new <id> [--mode автопилот\|пилот] [--region <код>]` | Создаёт `projects/<id>/` и делает проект активным |
| `strateg new <id> --from <проект>` | Копия проекта (чаще всего `example`): папка `projects/<проект>/` целиком, без `.tmp/` и кэша, под новым номером; делает копию активной и пишет в журнал событие «копия проекта». Источник не меняется. Хеши файлов и бюджет считаются заново, `cost.jsonl` копии пуст: время, стоимость, сбои, номер попытки шага и счёт остановок идут от копии, а расход на источник остаётся у него (сообщения сеанса, записанные до копирования, хук в копию не берёт). Ссылки `projects/<проект>/` в файлах копии команда не переписывает, а называет. Источник должен проходить `check`; если его меняли во время копирования, команду повторяют; `--mode` и `--region` с `--from` не нужны |
| `strateg use <id>` | Выбирает активный проект |
| `strateg status [--json \| --line \| --brief [--peek]]` | Состояние: шаг, ворота, источники, утверждения, время работы и время по часам (от первого до последнего события хода проекта, с ожиданием ответов и перерывами), стоимость, следующее действие; `--line` — одна строка статуса (без проекта — «Стратег: проекта нет», код 0: её показывает окно Claude Code); `--brief` — сводка «где остановились» не больше 10 строк: проект, режим, шаг, ворота, ждущие ответа, следующее действие, прерванные действия, файлы, изменённые вне агента, какие файлы выхода есть. Шаг, который ждёт ответа человека (после его «начато» последнее событие хода проекта — открытые ворота без ответа или «внеплановая остановка»; события хуков и «прервано» самой сводки не в счёт), сводка называет «на паузе» и говорит, чего ждём; такой шаг не прерывается, повторный `step start` не нужен. Обычный `--brief` — для нового сеанса: пишет «прервано» (начатое, не завершённое и не ждущее ответа действие, один раз); у шага «прервано» несёт `duration_s` — работу до последнего события хода проекта, простой до возобновления в неё не входит. `--brief --peek` — та же сводка без записи событий: для середины сеанса, например после сжатия контекста, идущий шаг прерванным не становится. «Изменено вне агента» (хеш файла не совпал с `state.yaml`, файл удалён или файл выхода положен рукой) пишет первая команда, которая сохраняет состояние, — по одному событию на файл и изменение; сводка называет такие файлы |
| `strateg step start <шаг>` / `strateg step done <шаг> [--next "<текст>"]` / `strateg step fail <шаг> --reason "<текст>"` | Начало, конец и ошибка шага; повторный `start` без `done` пишет «прервано», после `fail` шаг начинают заново |
| `strateg gate open <В1..В5> --questions <N>` / `strateg gate answer <В1..В5> --answer "<текст>"` | Ворота: открыть и записать ответ человека; ответ на В1 копирует текущую рамку в событие, рамки нет — отказ с подсказкой `strateg write` |
| `strateg mode <автопилот\|пилот>` / `strateg stop --reason "<текст>"` | Смена режима; внеплановая остановка в журнале |
| `strateg fetch <адрес> [--region <код>] [--refresh]` | Снимок страницы или PDF в `sources/`; соблюдает `robots.txt`, не заходит в локальную сеть; если в извлечённом тексте потерялись цены, берёт весь видимый текст; известный адрес отдаёт сохранённый снимок (недоступный прежде пробует заново в той же записи), а страница с уже снятым текстом нового `И-n` не получает. `--refresh` запрашивает страницу заново: тот же текст — отметка перепроверки у прежнего источника, другой — новый `И-n` со ссылкой `refreshes` (ответ называет утверждения на прежнем); недоступная страница прежнюю запись не меняет |
| `strateg add <путь> [--kind <вид>] [--consent <как получено, дата>]` | Регистрирует материал из `inputs/` как источник `И-n` с `path`, `text_path` и sha256. Вид по расширению: `.txt`, `.md` — «заметка пользователя»; `.pdf` — «PDF» (метки `[стр. N]`); `.docx` — «документ» (`[абз. N]`, `[таблица N]`, колонтитулы); `.xlsx`, `.csv` — «таблица» (лист и адрес ячейки, например `B2:`); `.pptx` — «презентация» (`[слайд N]`); изображения — «изображение» без текста; `--kind интервью` — расшифровка (`[строка N]`, в том числе для `.docx` и `.pdf`) и только с `--consent '<как получено, дата>'`: без отметки отказ со ссылкой на `knowledge/templates/consent.md`; отметка с датой `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД` (без имени и контактов собеседника) хранится у источника в `consent`, имена, телефоны и почта в тексте заменяются метками, а расшифровка всегда идёт путём персональных данных: снимок `inputs/i-<n>.txt`, исходник уходит из `inputs/` до `add --confirm`, который обязателен (имена латиницей и строчные не заменяются, названия сервисов и городов могут замениться: человек сверяет копию). Файл с «расшифровкой» в имени или с репликами двух собеседников по очереди без `--kind` — отказ с подсказкой, более слабые признаки — предупреждение. До модели ищет персональные данные: почту, телефоны, ИНН человека, СНИЛС, номера карт (номера 8-800 и ИНН организации не трогает). Нашёл — обезличенная копия `inputs/i-<n>.txt`, список замен (строка и метка, без значений), исходник уходит из `inputs/` в `.tmp/` проекта и в работу не идёт: цитировать такой материал нельзя, `check` и `pack` ругаются. Персональные данные в имени файла (телефон, почта, номер) считаются персональными данными: материал уходит так же, как при находке в тексте, под нейтральным именем и с категорией «имя файла»; изображение с такими данными в имени — отказ «переименуйте файл». Имена людей вне интервью — только предупреждение. Закрытые данные и обращения к ИИ — те же признаки и события, что у `fetch`. Повтор того же файла (sha256) отдаёт прежний `И-n`. Аудио и видео — отказ с просьбой дать расшифровку текстом |
| `strateg guide check <файл> [--json]` | Проверка гайда интервью по `knowledge/rubrics/interview-guide.yaml`: вопросы берутся из всех разделов «…вопросы…» и из пунктов со знаком «?», кроме разделов «Чего не спрашиваем» и «Что слушаем». Ошибка с номером вопроса и причиной — вопрос о будущем, наводящий, закрытый «да или нет» без продолжения, питч продукта, число вопросов не от 8 до 12; сомнительное (условное «бы», мнение, закрытый по форме) — предупреждение, код не меняет. Выводит и смысловые вопросы части Б для критика или агента. Код 0 — ошибок нет, 1 — есть |
| `strateg synth add --persona '<строка>' --file <файл> [--json]` | Беседа с модельным респондентом (пары «Вопрос n:» и «Ответ n: СИНТЕТИКА: …», обычно `.tmp/`) → источник вида «синтетика»: снимок `inputs/synth-<n>.md` со строками `[строка N]`, `sha256`, `persona`, `respondent_call` (след роли `respondent` в журнале; нет — «не подтверждён», сессия не независимая), недоверенный; ответ без метки «СИНТЕТИКА» — отказ. Утверждения на нём — только типа «синтетика» с цитатой ответа; факт, основание рекомендации, обещания, решения и `why` — ошибка `check`. Событие журнала — `actor: CLI` |
| `strateg add --confirm <И-n>` | Человек подтвердил замены: исходник уходит в `~/.strateg/private/<проект>/<И-n>/` вне проекта и архива, в `inputs/` остаётся обезличенная копия. Для изображения — подтверждение, что на нём нет персональных данных; до него цитировать изображение нельзя |
| `strateg source confirm <И-n>` | Человек подтвердил, что материал с признаками закрытых данных общедоступный: до этого цитировать его нельзя |
| `strateg claim add --file <путь\|->` | Записывает утверждение или список из YAML или JSON; цитата проверяется по снимку, без проверенной цитаты факт не записывается (у факта цитата не короче 3 слов и 20 знаков, все числа утверждения есть в цитатах) |
| `strateg claim replace <У-n> --file <путь\|-> [--by агент\|пользователь]` | Новое утверждение вместо действующего (те же проверки, что у `claim add`): связи `replaces` и `replaced_by`, статус «заменено» и строка истории у прежнего; предмет, период и регион сохраняются, иначе откат. Повтор отдаёт уже записанный номер. Места использования заменённого утверждения (варианты, обещания, строки плана) выводятся: их переписывает `write` |
| `strateg claim revoke <У-n> --reason "<текст>" [--by агент\|пользователь]` | Статус «отозвано», причина в истории статусов; повтор — «уже отозвано», код 0. Отзыв проходит всегда, места использования выводятся |
| `strateg claim list [--type <тип>] [--step <шаг>] [--plan-question <ВП-n>] [--status <статус>] [--json]` | Список утверждений; по шагу и вопросу плана скилл после перерыва получает уже записанное и дописывает недостающее |
| `strateg claim pairs [--ids У-1,У-2] [--all] [--json]` | Пары «утверждение — цитата» для классификатора: по умолчанию действующие утверждения с цитатой (кроме синтетики) ещё без вердикта. На пару — номер, тип, текст, период, регион и цитаты одной строкой (длинные обрезаны с «…»), помеченные как недоверенные (источник с обращением к ИИ — ещё и «подозрительный»). В `--json` поле `task` — готовое задание роли `classifier`: только пары; текст роли — тело обёртки `.claude/agents/classifier.md`, копия `knowledge/roles/classifier.md` (совпадение сверяет тест). Ничего не пишет |
| `strateg claim verdict <У-n> --verdict <вердикт> [--type-ok да\|нет] --reason '<строка>' --by классификатор\|агент --model <модель>` | Вердикт о смысле цитаты у утверждения (`verdict` в `claims.yaml`): «подтверждает», «частично», «не подтверждает», «не уверен». Вместо `<У-n>` и `--verdict` — `--file <ответ> --ids <пары>`: строгий разбор ответа роли, пара без разобранной строки — «не уверен». Строка ответа, которая повторяет цитату (целиком или причиной от 10 знаков), — тоже «не уверен». Повтор того же — без изменений; новый вердикт заменяет прежний, история — в журнале. «После повышения» помечен только повтор пар, которые к `route classifier --upgrade` были «не уверен», моделью повышения. При `классификатор` команда ищет в журнале событие «роль выполнена» для `classifier` на этом шаге после прошлой записи вердикта (его пишет хук `SubagentStop`); нет — в вердикте `classifier_call: не подтверждён`, в выводе и в `status` «вызов классификатора не подтверждён». «Не подтверждает» у основания рекомендации, обещания, решения или в `why` — ошибка `check`; основание без вердикта — предупреждение `status` «без проверки смысла цитаты» |
| `strateg write --file <путь\|-> [--by агент\|пользователь]` | Записывает файлы выхода одной транзакцией. Вход — YAML или JSON: ключи `frame`, `plan`, `gaps`, `options`, `promises`, `verification`, `decisions`, значение — содержимое файла без `schema_version` (у рамки без `version`). Вход проверяется моделью до записи; если после записи в проекте появились новые ошибки, все файлы, журнал и `history/` возвращаются, а выводятся только новые ошибки (прежние — предупреждение с числом). Те же данные — «без изменений», код 0. Перезапись кладёт прежний файл в `history/<имя>.v<N>.yaml`. Рамка до ответа на В1 — черновик (перезапись на месте), после ответа каждая правка — новая версия. Файлы, которые ссылаются друг на друга (`gaps` и `options`), пишите одним входом |
| `strateg event error --message "<текст>" [--step <шаг>] [--tool <имя>]` | Событие «ошибка» в журнале — из скилла или хука |
| `strateg check` | Проверяет активный проект; при ошибках код 1. Называет снимок `sources/i-<n>.txt` без записи в `sources.yaml` (потерянная запись: повторите `fetch`). Повтор «выполнено» с тем же ключом от гонки параллельных команд ошибкой не считает, если на адрес (цепочка `--refresh` — один источник) или файл один источник и его снимок цел |
| `strateg rubric check [--step <шаг>] [--json]` | Проверка полноты, часть А: 25 признаков рубрики `knowledge/rubrics/completeness.yaml`, каждый проверяет код, без модели. Показывает признаки, которые к шагу уже должны выполняться (по умолчанию шаг из `state.yaml`; на шаге 6 — все, кроме признаков шага 7): номер, имя проверки, «да» или «нет» и что дополнить — файл, запись, раздел. Код 0 — все «да», 1 — есть «нет». Ничего не пишет. Слова предметной области (А-22) берутся из `knowledge/rubrics/domain-words.yaml` |
| `strateg rubric record --file <путь\|-> --by <критик\|агент>` | Ответы критика на вопросы части Б — список `{id, answer: да\|нет, where, why}`: по одному на каждый вопрос, `where` и `why` непусты, «не знаю» нет; вопрос или его часть, которые начинаются со слова «Если», могут получить «да», если в `why` сказано «условия нет» и названы номера просмотренных записей. Работает с шага 6: на более раннем шаге часть А проверена не полностью, и итог не выносится. CLI сам прогоняет часть А на текущем шаге, выносит итог по `pass_rule` и пишет `completeness.yaml` (прежний — в `history/`) и событие журнала. Тот же вход повторно — «без изменений», кроме повтора после `route critic --upgrade`: это новая попытка, она записывается. В событии журнала — модель критика из последнего `route`. `--by` обязателен, значения по умолчанию нет: `критик` — ответы дал критик, `агент` — ответы дал сам агент, проверка не независимая, это видно в файле и в выводе. При `критик` команда ещё ищет в журнале событие «роль выполнена» для `critic` на этом шаге после прошлой записи проверки (его пишет хук `SubagentStop`); нет такого события — в `completeness.yaml` поле `critic_call: не подтверждён`, в выводе «Вызов критика не подтверждён», в JSON `independent: false`. Без хуков (другая среда) событие не появляется, и проверка остаётся неподтверждённой. **Коды выхода:** 0 — итог «пройдено»; 1 — итог «не пройдено» (`completeness.yaml` и событие журнала записаны); 2 — ошибка входа (формат ответов с номером вопроса, нет `--by`, шаг раньше 6), ничего не пишется. В `--json` поле `ok` равно «пройдено» |

### Ограничения `add` и проверки цитаты
- Строки, похожие на ключи (токены, пароль в строке подключения и подобное), заменяются меткой `[ключ]` по тому же порядку, что и персональные данные: обезличенная копия, показ замен без значений, исходник уходит вне проекта после `add --confirm`. Ключ в необычной записи (разбитый пробелами, закодированный) не находится.
- Детектор персональных данных ловит не всё (ADR-0011). Не находятся ИНН, записанный с пробелами по группам (`500 100 732 259`), и телефон из десяти цифр без `+7`, `8` и `7` (`9161234567`). Номер карты без разделителей заменяется, только если начинается с цифры от 2 до 6 и в нём не меньше 14 цифр (тринадцать — штрихкод EAN-13).
- У DOCX читаются абзацы, таблицы и колонтитулы. Надписи (текстовые рамки), сноски, комментарии и свойства файла (автор) не читаются и не проверяются: такой файл с персональными данными в них остаётся в `inputs/` как чистый.
- В заметке `.txt` или `.md` блок — строка. Если автор жёстко переносит строки (почта, markdown на 80 знаков), отрицание на следующей строке не видно: цитата, оборванная перед «не», пройдёт. В PDF строки внутри предложения склеиваются, там этого нет.

### Изображения, снимки экрана, аудио и видео
- Изображение модель видит напрямую, но только после `add --confirm`: человек подтверждает, что на нём нет людей и контактов. Код не сверяет смысл с картинкой. Он проверяет подтверждение, неизменность файла и место цитаты `экран <название>; элемент <что и где>`.
- Утверждение с изображения — факт об интерфейсе («кнопка серая»). «Пользователи не находят» — гипотеза с `check_method`: факт с такими словами `claim add` и `check` отклоняют. Рекомендация, где факты только с изображений, без гипотезы не проходит `check`.
- Разбор интерфейса идёт по снимкам экрана, которые дал человек (`knowledge/methods/ux-review.md`). Клики и сценарии в живом интерфейсе не разбираются: Playwright не подключён (ADR-0013).
- Аудио и видео (`.mp3`, `.wav`, `.m4a`, `.mp4`, `.mov` и подобные) `add` отклоняет: нужна расшифровка текстом.

### Ограничения `search`
- Это поиск по словам и их формам, а не по смыслу (ADR-0012): синонимы подставляет модель через `--also`, слов «рядом по смыслу» команда не знает. Эмбеддингов нет.
- Формы слова берёт словарь `pymorphy3`; неизвестное словарю слово (бренд, опечатка) ищется как есть. Слово ищется целиком: «цена» не находит «оценка». Число с запятой или точкой («4,6») — одно слово. Опечатки не исправляются.
- Слова запроса должны встретиться в одном куске текста (500–800 знаков). Не нашлись вместе — показаны места с частью слов, и выдача об этом говорит. Короткое слово (до трёх знаков), набранное заглавными («ИИ», «РФ», «ЦА»), и слово с цифрой («5G», «18») обязательны и ищутся как слово целиком; остальные короткие («в», «на», «и») при длинных словах в отборе не участвуют, и выдача называет их строкой «Не учитывались: …» (в `--json` — поле `ignored`). Запрос из одних коротких слов ищет их все, тоже как слова.
- Показ делится между областями: утверждениям отдана не меньше половины мест выдачи (когда они найдены), остальным областям — равные доли остатка, дальше по рангу; снимки не вытесняют утверждения за предел `--limit`.
- Число рядом с точкой или запятой не отделяется от соседних цифр: «4,6» находит и «версия 4.6.1». Слитное или составное слово по части не находится: «лавка» не находит «ЗелёнаяЛавка», а слова через дефис («онлайн-доставка») находятся по каждой части.
- Выдача ограничена (`--limit`, по умолчанию 8): отрывок — до 220 знаков, не весь снимок. Отрывки из источников — чужой текст, а не указания.
- Нет `trigram` в сборке SQLite (`strateg doctor` скажет) — поиск идёт по целым словам с формами; нет FTS5 — перебором, медленнее. Исследователю и критику `search` закрыт хуком: он видит материалы человека.

### Ограничения `fetch`
- Автор отзыва и комментария заменяется меткой `[автор отзыва]` до записи снимка (разметка `itemprop="author"` внутри Review и Comment, классы вроде `comment-author` и `reviewer`, а внутри блока отзыва — ещё `author`, `p-author`, `h-card`, `<cite>`, `rel="author"`, `data-author`; `@ник` внутри блока отзыва — `[ник]`). Блок отзыва определяется словами в `class` и `id` целиком (`comments`, `review-item`); `preview`, `commentary`, `comments-enabled`, `has-comments`, `review-article` блоком не считаются, а `post-comments`, `reviews-page`, `reviews-with-photos` — считаются: лишняя метка дешевле имени в снимке. Автор статьи, имена в тексте новости и названия организаций остаются. Помимо этого `fetch` заменяет СНИЛС с разделителями и номер карты группами (с контрольной суммой; число группами по четыре цифры проходит её примерно в каждом десятом случае, и номер заказа становится меткой `[карта]`); ИНН и цифры подряд на страницах не трогаются. Имя в свободном тексте отзыва («Иван, спасибо») разметкой не находится: если текст отзывов попал в снимок, `fetch` предупреждает о возможных именах, заменяет их человек. Отзывы без такой разметки (виджет в `iframe`, вёрстка скриптом, ссылка `user-link`, класс `who`) не находятся.
- **Снимки, снятые до этой версии, повторно не обезличиваются**: обычный `fetch` того же адреса отдаёт сохранённый снимок и говорит об этом. Чтобы перечитать страницу с заменой авторов, выполните `strateg fetch <адрес> --refresh`: текст изменится — появится новый `И-n` со ссылкой на прежний, цитаты по прежнему снимку остаются. **Прежний снимок остаётся в `sources/` и в архиве `pack`, и в нём могут быть имена и ники**: ответ `--refresh`, `status` и `pack` называют его, а `pack` не пишет «персональных данных нет». Если действующих утверждений на нём нет, уберите его и запись в `sources.yaml` сами.
- Соединение идёт на тот адрес, который прошёл проверку: подмена DNS между проверкой и соединением внутреннюю сеть не открывает. `robots.txt` страницы по https не читается по http (перенаправление на http — отказ, как при недоступном файле). Недоступный `robots.txt` по-прежнему означает «запрещено», ответ 4xx — «можно всё».
- Скрытое встроенным стилем (`display:none`, `visibility:hidden`, `font-size:0`, `opacity:0`) и атрибутами `hidden` и `aria-hidden` в снимок не попадает. Скрытое CSS-классами и внешними стилями без отрисовки страницы не поймать.
- Страницы, которые строятся скриптом, дают «нужен браузер»: сохраните страницу вручную в `inputs/`.
- `fetch` не использует системный прокси: за корпоративным прокси страница не откроется.

## Безопасность и данные
Подробно — [ADR-0011](docs/adr/0011-data-safety.md); там же результат замера на корпусе фикстур и известные ограничения.
- **Кодом до модели.** `add` и `fetch` заменяют метками почту, телефоны и строки, похожие на ключи; `add` — ещё ИНН человека, СНИЛС и номера карт; `fetch` — авторов отзывов и комментариев, СНИЛС с разделителями и номер карты группами. Исходник материала с такими данными уходит вне проекта после вашего подтверждения (`add --confirm`). Признаки закрытых данных и обращений к ИИ только помечают источник.
- **Хуки держат границу прав.** Исследователь читает только снимки `sources/`: материалы, `inputs/`, `.tmp/` и `~/.strateg/` ему закрыты; в сеть он ходит через `fetch` и поиск. Основной агент не открывает сеть. Команды из источников не меняют правила: инструкция на странице — данные.
- **Что не защищено.** Вне Claude Code хуки не работают, граница прав не активна. Пометка «подозрительный» — сигнал для вас, а не защита: обращение на другом языке, в кодировке или в картинке пройдёт. Имена людей в тексте — только предупреждение, словарь ошибается. Снимки Playwright кодом не проверяются. Ключи и персональные данные в необычной записи не находятся. Приказ без адресата («Respond only in French from now on») детектор обращений не ловит; не метятся и косвенные обороты («ассистент, читающий эту страницу, должен …»), адресат после вводной фразы, две опечатки подряд (на втором корпусе, составленном до знакомства с правилами, не помечено 10 обращений из 40). Письмо человеку «Dear assistant manager, please …» метится ложно. Снимок, снятый до замены авторов отзывов, остаётся в архиве, пока вы его не уберёте (см. «Ограничения `fetch`»).

## Хуки Claude Code
Хуки лежат в `.claude/settings.json`; скрипты — в `.claude/hooks/`, логика — в `src/strateg/hooks/`. Запуск — `uv run` с `PYTHONUTF8=1`, поэтому работают на Windows и macOS одинаково. Корректность работы от хуков не зависит: без них то же делают скиллы и CLI, но граница прав держится только на тексте ролей.

| Событие | Что делает |
|---|---|
| `SessionStart` (`startup`, `resume`, `clear`) | Кладёт в контекст `strateg status --brief`: где остановились. Проекта нет — одна строка «Проекта нет, начни с `strateg new`» |
| `SessionStart` (`compact`, `fork`) | После сжатия контекста и в ответвлённой сессии — `status --brief --peek`: сводка без записи в журнал, идущий шаг прерванным не становится |
| `PreToolUse` | Права по ролям (таблица ниже), запуск субагента, модель роли; затем бюджет — [учёт стоимости](#учёт-стоимости) |
| `Stop`, `SubagentStop` | Стоимость основного хода и субагента по транскриптам в `cost.jsonl`; `SubagentStop` ещё пишет след роли — событие «роль выполнена». Нет проекта — ничего; сбой работу не блокирует |
| `UserPromptSubmit` | Пока проект ждёт ответа на «внеплановую остановку», пишет событие «ответ человека» (только факт и время, текста сообщения в журнале нет): ожидание кончается в момент ответа, и работа до первой команды CLI засчитывается. Нет паузы или проекта — ничего; в вывод ничего не печатает; сбой работу не блокирует |
| `PostToolUseFailure` | Ошибка инструмента — событие «ошибка» в журнале (`strateg event error`): инструмент и текст, обрезанный, строки, похожие на ключи, вырезаны. Нет проекта — ничего |
| строка статуса | `strateg status --line` |

**Права в `PreToolUse`** (роль берётся из поля `agent_type` входа хука):

| Роль | Можно | Нельзя |
|---|---|---|
| Основной агент | Read в рабочей папке; Grep и Glob с `path` в папке активного проекта или в `knowledge/`; Write и Edit только в `outputs/` и `.tmp/` активного проекта; Bash; запуск `researcher`, `critic` и `classifier` | `WebSearch`, `WebFetch`, Playwright, `strateg fetch`, сетевые программы в Bash (`curl`, `wget`, `Invoke-WebRequest`, `python -c` с `urllib` и подобные), встроенные субагенты среды |
| `researcher` | `WebSearch`; чтение только в `sources/` активного проекта и в `knowledge/`; Bash — ровно `uv run strateg fetch '<адрес>'` с необязательными `--region <код>` и `--refresh`; Playwright — `browser_navigate` и `browser_take_screenshot` без `filename` | всё остальное |
| `critic` | Read, Grep, Glob в выводах активного проекта (в том числе `journal.jsonl` и `sources/`) и в `knowledge/` | `inputs/`, `.tmp/`, `state.yaml`, `cost.jsonl`, `completeness.yaml`, `history/` и всё остальное |
| `classifier` | — (текст роли — тело обёртки, пары — в задании из `claim pairs`) | любой инструмент |
| Все роли | — | `WebFetch`; чтение `.env`, `~/.strateg/`, `**/.tmp/pending/**`, `evals/`; правка `AGENTS.md`, `CLAUDE.md`, `.claude/` |

- Состояние проекта основной агент меняет только через CLI: `Write` и `Edit` файлов, которые пишет CLI (`state.yaml`, `journal.jsonl`, `cost.jsonl`, `sources.yaml`, `claims.yaml`, файлы выхода `*.yaml`, `history/`, `sources/`), — отказ с подсказкой. Документы в `outputs/` и входы команд в `.tmp/` пишет агент; запись в любое другое место (`src/`, `config/`, `knowledge/`, `.git/`) без `STRATEG_DEV=1` закрыта. Через Bash хук распознаёт перенаправления (`>`, `>>`, `>|`), `tee`, `sed -i` (и `-Ei`, `-ni`), `cp`, `mv`, `rm`, `touch`, `mkdir`, `ln`, `dd of=`, `copy`, `xcopy`, `ren`, `git checkout|restore|reset|clean|rm|mv` и командлеты PowerShell (`Set-Content`, `Out-File`, `Remove-Item`, `Rename-Item` …) и применяет ту же зону записи; файлы состояния CLI, `.tmp/lock` и `.tmp/cost/` через Bash закрыты и с `STRATEG_DEV=1`. Команда с записью и со сменой папки (`cd`, `pushd`, `Set-Location`) — отказ с подсказкой: пиши без `cd`, пути от корня репозитория. Файл блокировки `.tmp/lock`, учёт стоимости `.tmp/cost/` и папку `.tmp/` целиком агент не пишет и не удаляет.
- Поиск основного агента: `Grep` и `Glob` без `path` или вне активного проекта и `knowledge/` — отказ с подсказкой; `Grep` с `path` на корень проекта и рекурсивный `Glob` от корня (и от `.tmp/`) — отказ (искать в `outputs/`, `sources/` или по файлу: иначе поиск дойдёт до `.tmp/pending/`), плоский `Glob` вроде `*.yaml` разрешён; шаблон `Glob` с `evals` или с `..` — отказ. `evals/` закрыт и в Bash, в том числе `git show <ревизия>:evals/…`.
- Отказ — одна-две строки по-русски: что запрещено и что делать вместо. Он пишется в журнал событием «отказ хука» от `хук`. Для агента это подсказка, а не ошибка.
- Запуск субагента: разрешены роли, у которых есть и ключ в `config/routing.yaml`, и обёртка в `.claude/agents/`. Модель роли хук подставляет сам: берёт её из последнего события «выбор модели» этой роли на текущем шаге (его пишет `strateg route`, повышение `--upgrade` учтено) или, если `route` не вызван, из таблицы маршрутов с событием «route не вызван». Задание исследователю пишется в журнал; номер `ВП-n` из текста должен быть в `plan.yaml`, путей к `inputs/` и `outputs/` в задании быть не должно.
- Хук прав вызывается только для инструментов из `matcher` двух записей `PreToolUse` в `.claude/settings.json`. Первая — файлы, оболочка, субагенты, веб и Playwright. Вторая — остальные MCP, `Skill`, `SendMessage`, ресурсы MCP и `CronCreate`: основной агент проходит их как без хука (ни решения, ни бюджета, ни записи), исследователю, критику и классификатору — отказ. Инструменты вне обеих записей (`ToolSearch`, `TodoWrite` и другие) хук не видит: у классификатора их закрывает только `tools: []` в обёртке.
- Сбой хука прав блокирует вызов: «хук прав не сработал: …». Сбой остальных хуков, в том числе бюджета и учёта стоимости, работу не блокирует.
- Журнал и `state.yaml` хук и CLI пишут одним кодом (`src/strateg/storage.py`) под межпроцессной блокировкой папки проекта (файл `.tmp/lock`, Windows и POSIX) и через временные файлы с уникальными именами: параллельные хуки и команда CLI не теряют событий и не вызывают ложного «изменено вне агента». Время события ставится под блокировкой и не меньше времени последней строки журнала. Ожидание блокировки ограничено (хук — 5 с, в том числе при запуске роли, CLI — 30 с, хуки `SessionStart`, `PostToolUseFailure` — 10 с, `Stop`, `SubagentStop` — 9 с на все записи вместе): папка занята — понятная ошибка, а не вечное ожидание; отказ хука при этом остаётся отказом, а потерянное событие журнала названо в стандартном выводе ошибок. Замену `state.yaml` на Windows повторяют до того же таймаута (читатель-антивирус); не вышло — журнал возвращается к прежней длине и выдаётся ошибка, хеш и журнал не расходятся. Откат команды идёт под той же блокировкой; если файл заменить не удалось, команда называет файлы, оставшиеся записанными. «Граница прав не активна» пишется раз за сессию, проверка идёт под блокировкой. Файл блокировки `.tmp/lock` лежит в каждом проекте и в архив (`strateg pack`) не попадает. Команда, которая меняет проект, держит блокировку на всё изменение (читает проект заново под ней, пишет, при ошибке откатывает), поэтому параллельные `fetch`, `add`, `claim add` и другие команды не теряют записей друг друга и получают разные номера; сеть и разбор файлов идут до блокировки.
- Вход, не похожий на Claude Code (например, Cursor: нет `session_id` или есть `cursor_version`), роли не различить: права по ролям не применяются, раз за сессию пишется событие «граница прав не активна», охрана правил, `.env`, `~/.strateg/` и `.tmp/pending/` действует. Отчёт о прогоне пишет «граница прав не активна».

**Пределы.** Разбор Bash снижает риск, но не гарантирует защиту: команду можно записать иначе (имя подкоманды в переменной, свой скрипт вместо `-c`). Запись скриптами интерпретаторов (`python -c`, `node -e` и подобные), архиваторами (`tar`, `unzip`), `robocopy`, `git apply` и `[IO.File]::WriteAllText` хук не разбирает. Опора границы — то, что у основного агента нет веб-инструментов, а у исследователя нет чувствительного. Режим критика («возражения» или «полнота») хук не различает: `sources/` и `journal.jsonl` открыты ему всегда, а то, что в режиме «возражения» их читать не нужно, держит текст роли. Хук, не уложившийся в таймаут (15 с), вызов не блокирует — это свойство Claude Code. Список адресов разбора Playwright и сверку итогового адреса после перехода (`PostToolUse`) делает пакет подключения Playwright; сейчас хук держит только белый список инструментов, запрет `filename` и схему `http`/`https` у перехода.

## Учёт стоимости
Стоимость проекта считают хуки, без участия модели ([ADR-0010](docs/adr/0010-cost-budget.md)). Источник — транскрипты Claude Code и таблица цен `config/prices.yaml`; точность везде называется: «оценка» (токены × цены), «измерено» (доллары от среды, например `total_cost_usd` стенда `claude -p`), «нет данных».

- **Что берётся.** Из каждого сообщения ассистента: id, модель, токены ввода и вывода, чтения и записи кэша (на 5 минут и на час), число веб-поисков. Веб-поиск Claude Code в `usage` не пишет, поэтому считаются и уникальные по id блока вызовы `WebSearch` в сообщении: каждый стоит плату за поиск плюс запрос к модели поиска (`web_search_query` в `config/prices.yaml`, оценка; ключа нет — одна плата за поиск, и `cost report` пишет «модель поиска без цены»); поиски из `server_tool_use` одной платой, без удвоения. Текст разговора не читается и не хранится: в `cost.jsonl` и журнал идут только числа, id сообщения, модель, роль и шаг.
- **Когда.** `Stop` — конец хода основного агента (основной транскрипт), `SubagentStop` — конец работы субагента (его транскрипт лежит отдельно, в `<сессия>/subagents/`, и в основной не входит). Каждое новое сообщение — запись `cost.jsonl` с `message_id`, сессией, ролью (`agent_type`; основной агент — «основной», внутренние агенты среды — «служебный»), моделью, шагом из `state.yaml` и `cost_source: оценка`.
- **Без удвоения.** Сообщение учитывается один раз по id: одно сообщение пишется в транскрипт несколькими строками, повторный разбор и копия истории в другой сессии (ответвление, продолжение) расход не увеличивают. Разбор идёт с места, где остановился: смещения лежат в служебном файле `.tmp/cost/offsets.json` (в архив проекта он не попадает); обрезанный или переписанный файл разбирается с начала. Расход до команды `strateg step …` хук дописывает до её выполнения, поэтому сообщения старого шага остаются на старом шаге.
- **Битое пропускается.** Битая строка и сообщение без `usage`, id или модели пропускаются и считаются; число пропусков видно в `cost report`. Служебные сообщения среды (`<synthetic>`: ответ об ошибке API) денег не стоят и пропуском не считаются. Модель, которой нет в таблице цен, записывается с токенами и суммой «нет цены» (`cost_source: нет данных`), в журнал один раз на модель — событие «учёт недоступен».
- **Бюджет посреди хода.** После решения о правах `PreToolUse` перед платным вызовом (запуск субагента, `WebSearch`, `uv run strateg fetch`, инструменты Playwright), перед командами `strateg step …` и `strateg budget set …` дочитывает транскрипты всегда; перед остальными вызовами, которые исчерпание закрыло бы (Bash, Edit и другие), — не чаще раза в 5 с и не читая проект, если при прошлом пересчёте бюджета хватало (время пересчёта и это сведение лежат в `.tmp/cost/offsets.json`; агенту папка закрыта на запись — иначе он мог бы записать «бюджета хватает»). Расход сверяется с лимитом (`budget.py`). Со 100 % лимита денег или времени хук отказывает всем вызовам, кроме команд `uv run strateg …` (не `fetch`), чтения в папке проекта и записи в `outputs/` — для выпуска с пометкой о неполноте. Отказ называет, что кончилось (деньги, время или оба), и три ответа: добавить бюджет, выпустить с пометкой о неполноте, остановиться. С 80 % (`warn_share`) строка статуса предупреждает. Отказ — событие «бюджет» от `хук`, по одному на инструмент и состояние лимита.
- **Кто добавляет бюджет.** При исчерпании `uv run strateg budget set` с повышением лимита (любой лимит выше нынешнего, незнакомый флаг или число, которое не разобрать) хук не пропускает и не отказывает, а отвечает `ask`: среда спрашивает человека. В `claude -p` без человека это отказ. Понижение и `budget check` проходят. Хук работает только в Claude Code: вне хуков (CLI из терминала, другая среда) агент может поднять лимит сам, и в замере стенда это надо учитывать.
- **Сбой учёта и срок.** Транскрипт не прочитан, таблица цен не читается, проект не открылся или папка проекта занята: вызов пропускается, в журнале одно событие «учёт недоступен» на сессию, бюджет держат время и CLI. В событии только вид ошибки (`FileNotFoundError`), без текста исключения и путей. Вся бюджетная часть `PreToolUse` укладывается в 2 с на все ожидания блокировки (остаток передаётся дальше), запись события — не дольше 0,5 с, поэтому занятая папка не держит вызов до таймаута хука (15 с). Транскрипт пишется асинхронно и может отставать; хук не ждёт, последнее сообщение досчитает следующий хук.
- **Что хук не покрывает.** Матчер `PreToolUse` — файловые инструменты, Bash, PowerShell, Monitor, запуск субагента, `WebSearch`, `WebFetch` и Playwright: прочие инструменты (`Skill`, `TodoWrite`, MCP-серверы кроме Playwright) бюджет не закрывает. Вне Claude Code (Cursor, `claude -p` без хуков) бюджет держат скилл (`strateg budget check`) и отказ CLI на границе шага: это слабее.
- **Подписка.** `cost report` показывает эквивалент по цене API с пометкой «оценка», а не счёт и не долю лимитов.

`strateg cost report [--json]` собирает сводку из `cost.jsonl`. Таблица цен `config/prices.yaml` — все модели страницы цен, не снятые с API; её дата обращения и правила описаны в [config/README.md](config/README.md).

## Для разработчиков
`.claude/settings.json` действует в любой сессии Claude Code, открытой в этой папке, — в том числе когда вы разрабатываете сам продукт. Нужен Claude Code не ниже 2.1.295: блокировку вызова при сбое хука прав задаёт поле `onFailure`, которого нет в более ранних версиях. На старой версии падение до запуска скрипта (нет `uv`, нет `.venv`) вызов пропустит, то есть граница прав не держится.
- **Правка правил** (`AGENTS.md`, `CLAUDE.md`, `.claude/`) закрыта, как и запись основного агента вне `outputs/` и `.tmp/` активного проекта (`src/`, `config/`, `knowledge/`, `.git/`). Запустите среду с `STRATEG_DEV=1`: Windows PowerShell — `$env:STRATEG_DEV = "1"; claude`, macOS и Linux — `STRATEG_DEV=1 claude`. Переменная снимает охрану правил, зону записи и ограничение поиска `Grep`/`Glob` основного агента (без `path` и вне проекта можно); права ролей, `.env`, `~/.strateg/`, `.tmp/pending/`, `evals/` (для Read и Bash), отказ на поиск по всей папке проекта и запрет записи в файлы состояния (в том числе через Bash) остаются в силе. В режиме разработки поиск без `path`, от корня продукта или от `projects/` не проверяется и может дойти до `evals/` и `.tmp/pending/`.
- **`evals/`** для Read, Grep, Glob и Bash закрыт всем: смотрите его в обычном терминале или в сессии, открытой в другой папке.
- **`STRATEG_HOOKS=0`** выключает все хуки — только для замера их пользы (сценарии С-2, С-9, С-10 и С-13 б). Задаёт её человек при запуске среды.
- `uv run strateg doctor` и `uv run strateg status --brief` показывают, что переменная задана.
- Тесты и `uv run` из папки продукта от хуков не зависят: хуки работают только внутри сессии Claude Code.
- Нет `uv` в `PATH` или не создаётся `.venv`: хук прав блокирует вызовы. Почините `uv` или запустите с `STRATEG_HOOKS=0`.
- Личные настройки среды — в `.claude/settings.local.json` (в git не попадает).

## Требования
- Python 3.12 через [uv](https://docs.astral.sh/uv/) (uv сам поставит нужный Python).
- Одна из сред: Claude Code (основная), Cursor, OpenCode. Копии скиллов в репозитории нет; для Codex один раз запустите `uv run python scripts/sync_skills.py --dest .agents/skills` — агент в Codex не проверялся. GigaCode не поддерживается.
- Платных сервисов сверх подписки на модель в вашей среде не нужно.
- Сканер секретов `gitleaks` ставить не нужно: `pack` ищет ключи встроенными шаблонами, а если `gitleaks` есть в PATH, запускает и его.
