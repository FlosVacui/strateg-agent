# Стенд оценки

Кейсы, прогон агента на кейсе без человека и (позже) сравнение с обычным чатом и аналитиком вручную. Готовы кейсы и стенд прогона `evals/run.py`; судья и сравнение добавляются позже.

## Кейсы
Кейсы лежат в `evals/cases/<id>/`. Метод оценки описан в [ADR-0015](../docs/adr/0015-evaluation.md).

В каждой папке два файла:
- `card.yaml` — карточка кейса, **только то, что знает руководитель**: первое сообщение, роль, срок и ограничения, материалы, ответы на вопросы ворот В1–В5, правило выбора варианта на В4, то, чего он не знает, и реакция на внеплановую остановку. По карточке отвечает синтетический руководитель. Читается `yaml.safe_load`.
- `expected.md` — ориентиры для судьи: что агент должен найти, ловушки и чем считается провал. Руководитель и агент его не видят. Готового ответа и верного варианта там нет: судья оценивает качество, а не совпадение с мнением авторов.

Кейсы:

| Кейс | Вид | Назначение |
|---|---|---|
| [`fraud-protection`](cases/fraud-protection/card.yaml) | учебный | «Ева» и «Семейная безопасность +»: основной сценарий С-1 и отладка агента |

**Кейс разработки.** `fraud-protection` — кейс, на котором агент отлаживается и показывается. Поэтому он **не входит** в сравнения: ни «агент против обычного чата», ни «агент против аналитика вручную» — его результаты подгонялись бы под агента. Для замера берутся другие кейсы, которые команда при отладке не использовала. По [ADR-0015](../docs/adr/0015-evaluation.md) отдельно обязателен новый кейс, которого команда не видела.

**Требование к прогону: агент не должен видеть ответов.** Ориентиры лежат в том же репозитории, что и агент. Путь пользователя в `docs/user-journey.md` содержит этот кейс и названия закрытых показателей, а `projects/demo/` — демо-проект того же кейса. Поэтому прогон идёт только в отдельной копии продукта:
- копия лежит вне репозитория продукта и рядом с ним нет других рабочих папок разработки;
- в копии нет `evals/`, `docs/`, `projects/demo/`, `projects/example/` и проектов прошлых прогонов — агенту нужны `AGENTS.md`, скиллы, `knowledge/` и CLI;
- автопамять среды выключена;
- перед стартом поиск строк кейса по копии пуст, например `grep -r "Защита близких"`.

Эти условия обеспечивает `evals/run.py`: копию он собирает сам и проверяет перед стартом (см. ниже). Вручную копию собирать не нужно.

Правила для карточек: только открытые данные, без имён людей и без закрытых данных компании; у цены и названия указаны регион и дата.

## Рубрика
Рубрика полноты лежит в `knowledge/rubrics/completeness.yaml`, а не здесь: её видит агент и критик внутри прогона. Она общая для любой задачи: проверяет, что всё названо и связано (поля, перечень показателей, ворота, обещания), и не содержит ни слова об учебном кейсе.

Ориентиры судьи — `expected.md` кейса — другое. Они свои для каждого кейса, закрыты от агента и оценивают качество и верность по существу кейса. Рубрика этого не делает. Судья видит и рубрику, и ориентиры; ориентиры в рубрику не переносятся. Перед прогоном поиск строк кейса по `knowledge/` пуст, как и по остальной копии.

## Прогон: `evals/run.py`
Стенд прогоняет агента на кейсе без человека. Ворота — конец вызова `claude -p`; на воротах отвечает синтетический руководитель по карточке кейса, и прогон продолжается через `--resume`.

```
uv run python evals/run.py <кейс> [--mode автопилот|пилот] [--model …] [--max-calls N] [--budget-usd X] [--max-minutes M] [--record]
uv run python evals/run.py <кейс> --dry-run
```

Что нужно на машине:
- `uv`: стенд сам собирает копию во временной папке и делает в ней `uv sync` (нужна сеть для зависимостей, если их нет в кеше `uv`);
- `claude` в PATH и выполненный вход в том профиле, где идёт прогон; без `claude` код выхода 2. Проверка цикла без `claude` и без сети — `--dry-run`;
- сеть для веб-поиска агента.

Как устроен прогон:
1. **Копия.** Только `AGENTS.md`, `CLAUDE.md`, `.claude/`, `knowledge/`, `src/`, `schemas/`, `config/`, `pyproject.toml`, `uv.lock`; без `evals/`, `docs/`, `tests/`, `scripts/`, проектов и `.git`. README в копии — заглушка. Перед стартом поиск строк кейса (названия из карточки и ориентиров, адреса источников, строки из `evals/leak-phrases.yaml`), путей репозитория и символических ссылок по копии должен быть пуст, иначе отказ и код 2. Окружение копии своё (`uv sync`).
2. **Вызов.** `claude -p --output-format json --model <модель>`; сообщение идёт по stdin. Модель основного агента задана явно (по умолчанию `sonnet`, `--model` меняет) и записывается в итоги, как и фактические модели из `modelUsage`. Права явно: `--permission-mode acceptEdits` и `--allowedTools` (веб-поиск, `Read`, `Grep`, `Glob`, запись файлов проекта, роли и команды `strateg`; произвольный `Bash`, например `curl`, и `WebFetch` не разрешены). `--dangerously-skip-permissions` и `--bare` не используются: хуки и `.mcp.json` копии работают, агент проверяется как есть. `--setting-sources project` и `--strict-mcp-config`: настройки профиля (плагины, `env`, `model`) и пользовательские MCP-серверы в вызов не идут. Предохранители: `--max-turns` на вызов (по умолчанию 200) и `--max-budget-usd` на остаток бюджета. Тайм-аут вызова завершает всё дерево процессов (`taskkill /T /F` на Windows, группа процессов на POSIX).
   - **Среда вызова.** Без `STRATEG_*` (в том числе `STRATEG_HOOKS`: иначе хук прав выключался бы), без `CLAUDE*` родителя, кроме нужных для входа (`CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_*`, `CLAUDE_CODE_GIT_BASH_PATH`), без `VIRTUAL_ENV`. В `PATH` `.venv` копии первым, `.venv` репозитория убран: `strateg` в вызове — команда копии.
   - **Второй барьер.** В настройках вызова `permissions.deny` закрывает `Read`, `Grep`, `Glob`, `Edit`, `Write` по путям репозитория, его рабочих копий (`git worktree list`), соседних папок с итогами и `projects/` профилей Claude. Первый барьер — хук прав продукта в копии.
3. **Ожидание.** После каждого вызова стенд читает `strateg status --json` в копии и журнал проекта: ворота ждут ответа (`waiting_gates`) — ответ из `gates` карточки; остановка — `paused` равно «остановка» или последнее событие хода проекта в журнале — «внеплановая остановка» (журнал читается и сам: так остановка видна и в проектах прежней версии CLI) — ответ из `off_card.stops`; шаг 7 закрыт — выпуск, конец; иначе агент закончил вызов без записи ожидания — вопрос без ворот. Если `status --json` не прочитан (не запустился, не JSON, ошибка не «проекта нет») — это сбой прогона, код 1: «вопросом» он не считается. Вызов, который упёрся в `--max-turns` без ожидания, — не сбой: стенд отвечает «продолжай» в ту же сессию, вызов засчитан, число таких ответов — `turn_limit_continuations`.
4. **Ответы.** Правилами по карточке, без второй модели. В1 — ответы карточки и режим одной строкой. В2, В3, В5 — первый ответ карточки. В4 — по `gaps.yaml` и `options.yaml` проекта: если есть пробел, влияющий на выбор, закрываемый открытым источником не дороже $1 и 10 минут, и закрытие ещё не запрашивали — «сначала закрой П-n»; иначе номер рекомендованного активного варианта, а если рекомендация неактивна — наименьший активный (`b4_choice_rule`). Остановка — по словам причины в журнале, взятым из скиллов и `AGENTS.md` («бюджет израсходован», «оценка плана больше остатка бюджета», «признаки закрытых данных», «проверка полноты не прошла», «новые сведения противоречат», «причина из пре-мортема», `robots`); тест сверяет их с текстом скиллов. Вопрос про срок и получателя — из `persona`. Вопрос о бюджете проекта (сколько добавить, на какую сумму увеличить лимит; не «бюджет клиента») — из `off_card.budget_question`, после срока и получателя; ответ помечается в `notes`.
5. **Конец.** Выпуск; либо предел вызовов, бюджета (`--budget-usd`) или времени (`--max-minutes`); либо три вызова подряд без изменений в проекте («зацикливание»).

Автопамять выключена (`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` и `autoMemoryEnabled: false` в настройках вызова), пользовательский `CLAUDE.md` и правила профиля исключены через `claudeMdExcludes`. Профиль всё же влияет на прогон: вход, пользовательские навыки в каталоге профиля и MCP-серверы в `~/.claude.json` стенд может не отсечь полностью; поэтому в итогах записаны профиль (`config_dir`), версия `claude`, фактические модели и коммит продукта.

Итоги — `evals/runs/<кейс>/<время>/` (папка не в git):
- `result.json`, пишется после каждого вызова: исход, число вызовов, время по часам, время работы агента (журнал проекта), стоимость — последнее накопительное значение `total_cost_usd` и `modelUsage` с субагентами, ворота и ответы, остановки, вопросы без ворот, «прервано», ответы вне карточки (`off_card`) с пояснением, итог `strateg check`, итог проверки полноты (`completeness.yaml`), путь к копии проекта; версия `claude`, профиль, фактические модели (`actual_models`), коммит продукта и признак незафиксированных правок. Стоимость вызова берётся и у упавшего вызова; значение меньше прежнего накопительным не считается (остаётся максимум, запись в `notes`);
- `raw/call-NN.json` — сырые ответы `claude -p`;
- `project/` — копия проекта.
`--record` добавляет строку в таблицу [`docs/benchmark.md`](../docs/benchmark.md); с `--dry-run` флаг не работает.

Коды выхода: 0 — выпуск; 1 — ошибка вызова, `is_error`, тайм-аут, не прочитанный `status` (частичные итоги записаны); 2 — `claude` не найден, кейс не по формату, в копии нашлись строки кейса; 3 — предел вызовов, бюджета (в том числе `error_max_budget_usd` самого `claude`, он приходит с кодом 1), времени или зацикливание (итоги записаны, выпуска нет).

**Ответ вне карточки.** Если по карточке ответ выбрать нельзя, руководитель отвечает «Не знаю, решите сами и запишите допущение», а прогон отмечает это в `off_card`. Так бывает: остановка с причиной, которой нет в `off_card.stops` (например, «нужен материал»: в `notes` записано, чего не хватило); вопрос без ворот (если он не про закрытые данные из `unknown_and_closed` и не про срок и получателя из `persona`; пункт закрытых данных узнаётся по показателю и ещё одному слову из пункта, только в предложениях со знаком вопроса); В4 без читаемого `options.yaml`. Условные правила, зависящие от текста ворот (В3: закрытие пробела), по тексту не применяются: стенд даёт первый ответ и пишет это в `notes`.

Ограничения:
- Стенд не судит качество: судья, рубрика сравнения, сравнение с обычным чатом и абляции — следующие шаги.
- Ответы детерминированные; руководитель на модели — расширение на потом.
- `--dry-run` проверяет цикл, а не агента: подменённый `claude` исполняет заготовленные команды CLI на проекте-примере.
- Не проверено на настоящем `claude`: действие `claudeMdExcludes` на пользовательский `CLAUDE.md`, нужность каждого пункта списка `--allowedTools`, сохранение `session_id` при `--resume` (стенд берёт последний полученный), запись путей в `permissions.deny` (форма `//c/…` на Windows), действие `--setting-sources project` и `--strict-mcp-config` на пользовательские навыки профиля и MCP-серверы, `claude --version`, поведение при `error_max_turns`; отдельный тест «исследователь вызывает `curl`» (нужен настоящий `claude`) не сделан. Это сверяется на настоящем прогоне.
- Стоимость на подписке — эквивалент по цене API, а не счёт.
