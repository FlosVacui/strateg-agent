# Проекты

Каждая задача руководителя продукта — отдельная папка `projects/<id>/`: материалы, снимки источников, состояние работы, журнал, выводы и готовые документы.

Проекты пользователя хранятся локально и в git не попадают (`.gitignore` закрывает всё в `projects/`). В репозитории лежат только две папки:

- `projects/example/` — пример заполненного проекта;
- `projects/demo/` — демонстрационный проект для показа.

Свою задачу заводите в папке с любым другим именем, например `projects/mobilnoe-prilozhenie/`.

## Продолжить пример
Пример не правят: его копируют и продолжают копию.

```
uv run strateg new moy-primer --from example
uv run strateg status
```

Команда копирует `projects/example/` в `projects/moy-primer/` и делает копию активной. Дальше работа идёт как в любом проекте: `status` показывает шаг, ворота и строку «Дальше», команды и скиллы продолжают с места остановки. В агенте достаточно сказать «продолжи пример».

- `projects/example/` не меняется: ни файлов, ни блокировки.
- В копию не входят `.tmp/` и `.cache/` (блокировка, материалы до подтверждения замен, кэш `fetch`) и исходники с персональными данными из `~/.strateg/private/`.
- Журнал копии начинается прежними событиями; в конце — событие «копия проекта»: откуда, на каком шаге и воротах остановлен пример.
- Время работы, стоимость, сбои и номер попытки шага считаются от этого события. `cost.jsonl` копии пуст, бюджет — как у нового проекта. Расход на пример остаётся в нём и назван в событии; сообщения сеанса, записанные до копирования, в копию не попадают.
- Ссылки вида `projects/example/…` в файлах копии команда не переписывает (сломались бы хеши цитат), а называет в ответе: поправьте их при необходимости.
- Копия собирается во временной папке рядом и встаёт на место `projects/<номер>/` в конце: после сбоя полупапки не остаётся. Если пример меняли во время копирования, команда скажет об этом: повторите её.
- `check` копии чист, а «изменено вне агента» не возникает: номер проекта и хеши файлов записаны заново.
