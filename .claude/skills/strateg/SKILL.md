# Вход, продолжение и управление

Цель: за один-два хода понять, где проект, показать это человеку и передать работу скиллу шага. Шагов этот скилл сам не выполняет.

## 1. Сводка в начале разговора
1. Первый ход нового чата — `uv run strateg status --brief` по правилу «Первый ход» из `AGENTS.md`: один вызов за чат. Уже вызывал — читай `uv run strateg status`.
2. Ответ «активный проект не выбран» — раздел 2. Иначе — раздел 3.

## 2. Активного проекта нет
- Посмотри папки в `projects/`. По каждой, кроме `example` и `demo`: шаг и «Дальше» — из `uv run strateg status --project <id>`, дата — время последней записи в её `journal.jsonl`. `example` и `demo` покажи отдельно, как примеры.
- В сообщении есть задача — раздел 4.
- Человек назвал проект из списка — `uv run strateg use <id>`, затем раздел 1 для него.
- Задачи нет — ответь коротко:
  - что ты делаешь: от размытого запроса до продуктовой и коммуникационной стратегии с источниками, вариантами, пробелами и планом проверки;
  - как начать: написать задачу своими словами и, если есть, ссылку;
  - пример: «Запускать ли доставку готовых обедов для офисов и что обещать по срокам?»;
  - материалы: файлы — в папку проекта `inputs/`, путь назовёшь, когда заведёшь проект; ссылки — в чат;
  - список проектов, если они есть.

## 3. Проект есть: где остановились
Сводка — до десяти строк: проект и режим, шаг, ворота, «Дальше», прерванное, изменённое вне агента, файлы выхода.

1. **«Изменено вне агента: <файл>»** — скажи человеку, какой файл изменён не через CLI. Руками его не правь и не откатывай. `uv run strateg check`: ошибки по этому файлу — внеплановая остановка с пересказом ошибки.
2. **«Прервано: шаг N»** — `uv run strateg step start <шаг>`: это новая попытка того же шага, без неё `step done` откажет. Записанное не теряется. Прервано другое действие, например `fetch`, — повтори его, только если оно ещё нужно: снимок и утверждение CLI не задвоит.
3. **Что уже сделано на шаге:** `uv run strateg claim list --step <шаг>`. На шаге `2б` — по каждому вопросу плана: `uv run strateg claim list --step 2б --plan-question <ВП-n>`. Файлы выхода из сводки и документы в `outputs/` прочитай. Снимки из `projects/<id>/sources.yaml` заново не скачивай. Сделанное не повторяй, допиши недостающее.
4. **Сводка человеку** — коротко:
   - проект и шаг;
   - последнее действие: последние записи `projects/<id>/journal.jsonl`;
   - следующее действие: строка «Дальше»;
   - расход: время и стоимость из `uv run strateg status`, своих подсчётов нет;
   - принятые допущения: `uv run strateg claim list --type допущение --status действует` — сколько и главные;
   - строка `uv run strateg status --line`, дословно.

   Сообщение человека — ответ на ждущие ворота (правило из `AGENTS.md`) или на остановку: сводку сократи до одной строки и сразу иди к разделу 5.
5. Проект есть, а сообщение человека — новая задача (не ответ на ворота, не фраза управления, не продолжение): не продолжай и не заводи проект молча. Спроси: «Это продолжение проекта <id> или новая задача?» По ответу — раздел 5 или раздел 4.
6. Дальше — раздел 5.

## 4. Новая задача
- Активный проект занят другой задачей — заводи новый, прежний остаётся. Вернуться к нему — `uv run strateg use <id>`.
- `uv run strateg new <id>`. `<id>` — строчные латинские буквы, цифры и дефис, по смыслу задачи, например `obedy-ofisam`. «Уже существует» — возьми другое имя или `use`, если это та же задача.
- Режим не спрашивай отдельным ходом: он — строка на В1. Человек сам сказал «пилот» — `uv run strateg mode пилот`.
- Назови путь для файлов: `projects/<id>/inputs/`.
- Дальше — шаг 1: прочитай `.claude/skills/frame/SKILL.md` целиком.

## 5. Куда передать работу
| Что в сводке и сообщении | Скилл и раздел |
|---|---|
| Ждёт В1, сообщение — ответ | `frame`, «Ответ на В1» |
| Ждёт В2 или В3, сообщение — ответ | `research`, ворота этого шага |
| Ждёт В4, сообщение — ответ | `options`, «После ответа» |
| Ждёт В5, сообщение — ответ | `package`, «Ворота В5» |
| Ворота ждут, а сообщение — фраза управления или вопрос | Правило из `AGENTS.md`: выполни фразу или ответь, повтори вопрос ворот. Ворота не закрывай |
| «Дальше: Внеплановая остановка…» | Сообщение человека — ответ: действуй по нему в скилле текущего шага |
| Шаг в работе или «Дальше: шаг N» | Скилл шага по таблице «Путь» в `AGENTS.md` |
| Шаг 7 выполнен | Выпуск готов: ссылки на `outputs/one-pager.md`, `outputs/report.md`, `outputs/run-report.md`. Сопровождение решения — в следующих версиях |

Ответ на ворота записывает скилл ворот, в своём порядке: у В1 сначала рамка через `write`, потом `gate answer`. Перед первой командой прочитай `.claude/skills/<скилл>/SKILL.md` целиком.

## 6. Фразы управления
Таблица фраз и порядок пересчёта — в `AGENTS.md`. Здесь только то, чего там нет.
- **«стоп»** — новых команд не запускай. Скажи, что успел (последняя команда и её итог) и с чего продолжишь. На следующем ходу — `uv run strateg status` и продолжение.
- **«статус», «где мы»** — проектов несколько: добавь их список по разделу 2. Открытые вопросы плана и ворота назови.
- **«сколько потрачено»** — время и стоимость из `uv run strateg status`, дословно. «Нет данных» — так и скажи, своих оценок не добавляй.
- **«пилот», «автопилот»** — после смены скажи, на каких воротах теперь остановишься: пилот — В1–В5, автопилот — В1 и В4.
- **«уточни: …»** — скилл `frame`, раздел «Уточни» после В1. До ответа на В1 это ответ на В1.
- **«исправь У-n: …»** — `.claude/skills/research/claims.md`, «Исправить, заменить, отозвать». В правке ссылка — сначала `fetch`. Ссылки нет или цитата не нашлась — допущение с `origin: пользователь`, скажи об этом человеку.
- **«в плане: …», «в картине: …»** — скилл `research`, «Правки человека». **«В вариантах: …»** — скилл `options`. **«В стратегии: …»** — скилл `strategy`. Файл выхода меняй через `write --by пользователь`, документ — Write.
- **«откуда это?»** — по номеру `И-n` из утверждения смотри `projects/<id>/sources.yaml`: адрес, дата обращения, путь к снимку.

## Особый отказ
«Проект не найден» — список по разделу 2, затем `use`. Остальные отказы и сбои — по `AGENTS.md`.
