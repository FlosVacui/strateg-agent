# Шаг 7. Выпуск (В5)

Цель: руководитель получает одну страницу для решения, отчёт и честный отчёт о прогоне. Все числа и номера — из файлов выхода и утверждений, новых сведений в документах нет.

## Вход
- `uv run strateg status`. Шаг 6 выполнен — иначе сначала скилл `strategy`. Исключение — человек ответил «выпустить» на остановку: тогда раздел «Выпуск с пометкой о неполноте».
- `uv run strateg check` без ошибок.
- Читай `options.yaml`, `verification.yaml`, `promises.yaml`, `outputs/situation.md`, обе стратегии, `outputs/verification-plan.md`.
- Шаг уже начат: посмотри, какие документы в `outputs/` уже есть, и допиши недостающие. `decisions.yaml` есть — прочитай, не пиши заново.

## Работа
1. `uv run strateg step start 7`.
2. **Запись решения.** Выбор человека на В4 — решение `Реш-1`. Сегодняшнюю дату возьми командой `date +%F`. Поля:
   - `option` — `chosen`; `rejected` — остальные варианты;
   - `basis` — утверждения из `recommendation.claims`; `assumptions` — допущения или гипотезы, на которых вариант держится;
   - `expected` — ожидаемое изменение;
   - `owner` — роль из строк плана проверки, без ФИО;
   - `conditions` — условия отказа: каждое «передумаю, если» и каждая причина пре-мортема. У условия показатель, порог с цифрой, дата, действие, `origin` и `row` — строка плана, порог которой совпадает с порогом условия;
   - `review_date` — дата пересмотра;
   - `commitments` — только обязательства, которые назвал человек, со сроками и владельцами; нет таких — не пиши поле;
   - `status: действует`.
   - Человек назвал владельца и дату — запиши их. Нет — это предложение агента: владелец из плана проверки, дата пересмотра — самый поздний срок строки плана плюс запас от сегодняшней даты, даты условий — срок пересмотра. Такие значения помечай «предложено агентом» в документах и подтверждай на В5.

3. Запиши: `projects/<id>/.tmp/decisions.yaml`, затем `uv run strateg write --file projects/<id>/.tmp/decisions.yaml`. Даты — строки в кавычках. Образец входа в минимальном виде:

```yaml
decisions:
  decisions:
    - id: Реш-1
      option: Вар-2
      basis: [У-2, У-5]
      rejected: [Вар-1, Вар-3, Вар-4]
      assumptions: [У-4]
      expected: "Постоянными клиентами станут от 15 до 25 офисов за полгода"
      owner: "руководитель направления"
      conditions:
        - metric: "число офисов с повторным заказом за месяц"
          threshold: "меньше 5 офисов"
          date: "2027-03-01"
          action: "перейти к варианту Вар-3"
          origin: "передумаю, если"
          row: ПП-1
      review_date: "2027-03-01"
      status: действует
```

4. **Одна страница — `outputs/one-pager.md`.** Не больше одной страницы A4, около 300 слов. Разделы — по шаблону `knowledge/templates/one-pager.md`: заголовки и порядок не меняй, `<…>` замени текстом.
   Обещание со статусом «не подтверждено» сюда не попадает. Число, которое компания сообщает о себе, — «по данным компании». «Кратко» — пересказ разделов ниже, из номеров только вариант, без кодов `Б-n`; в разделах — не больше двух номеров в скобках в конце предложения.
5. **Отчёт — `outputs/report.md`.** Разделы — по шаблону `knowledge/templates/report.md`: заголовки и порядок не меняй, `<…>` замени текстом.
6. **Проверка полноты.** Пройди `.claude/skills/strategy/completeness.md` ещё раз целиком, включая признаки шага 7 (`rubric check --step 7`, критик, `rubric record`). Что не прошло — доработай. После доработки не прошло — `uv run strateg stop --reason '<признаки>'`: выпустить с пометкой о неполноте или уточнить рамку. Выпуск с пометкой после ответа человека проверку не повторяет.
7. **Отчёт о прогоне — `outputs/run-report.md`.** Разделы — по шаблону `knowledge/templates/run-report.md`: заголовки и порядок не меняй, `<…>` замени текстом. Что писать:
   - «Проверка полноты»: итог — из `projects/<id>/completeness.yaml` (его пишет `rubric record`): признаки, ответы, итог, кто отвечал. По памяти не пересказывай. Отвечал агент — «не независимая: проверял тот же агент». Отвечал критик — «критик той же семьи моделей, что и основной агент: самопредпочтение уменьшено, но не устранено». В файле «вызов критика не подтверждён» — так и напиши: след вызова критика не найден.
   - «Среда»: какие роли шли субагентами, какие исполнял сам агент — по событиям «выбор модели» в журнале (`route`; у запасного пути в причине «исполняет основной агент»).
   - «Время и стоимость»: числа — из `uv run strateg cost report` и `uv run strateg status`, вызванных после записи решения, перед `step done 7`. Из `cost report` — итог и его точность, роли, шаги, веб-поиск, пропуски разбора, модели без цены, повышения модели; из `status` — время: работа и по часам (подпись: «по часам N мин (с ожиданием ответов и перерывами)»). Другие суммы из ранних вызовов не бери. По памяти не считай.
   - «Ограничения этой версии»:
     - «граница прав не активна» — если не Claude Code с хуками (правило «Как узнать среду» в `AGENTS.md`);
     - «модель роли не гарантирована» — если модель роли не задавалась;
     - граница для текста из веба не работает — если исследователя исполнял сам агент;
     - «бюджет проверялся на границах шагов, а не посреди хода» — только если среда не Claude Code с хуками. В Claude Code с хуками — не пиши.

## Выпуск с пометкой о неполноте
Человек ответил «выпустить» на остановку: проверка полноты не прошла или бюджет исчерпан.
1. Закрой текущий шаг: проверка полноты не прошла — `uv run strateg step done 6 --next 'выпуск с пометкой о неполноте: <признаки>'`; бюджет кончился на другом шаге — `uv run strateg step done <шаг> --next 'выпуск с пометкой о неполноте'` или `step fail <шаг> --reason 'бюджет израсходован'`. Затем `uv run strateg step start 7` и `uv run strateg budget check --action выпуск`: выпуск берёт резерв бюджета.
2. Пиши документы из того, что есть. Если для документа нет файлов выхода, его не пиши и назови в `outputs/run-report.md` в разделе «Не сделано». `decisions` записывай, только если в `options.yaml` есть `chosen`.
3. Первой строкой раздела «Кратко» в `outputs/report.md` и `outputs/run-report.md` — «Неполно: <признаки, которые не прошли, или что не сделано>»; в `outputs/one-pager.md` — словами.
4. В `outputs/run-report.md`, раздел «Проверка полноты»: список непройденных признаков и ответ человека «выпустить». Проверку и остановку не повторяй.
5. Дальше — В5 как обычно.

## Ворота В5
- Пилот: `uv run strateg gate open В5 --questions <N>`, пришли документы со ссылками на файлы и строкой `uv run strateg status --line`. Среди вопросов — подтверждение значений, предложенных агентом (владелец, дата пересмотра, обязательства). Жди. Ответ — `uv run strateg gate answer В5 --answer '<ответ дословно>'`. Правка — порядок пересчёта из `AGENTS.md`, затем снова В5.
- Автопилот: `uv run strateg gate open В5 --questions 0`, пришли итог сообщением: что рекомендуем одной строкой, предложенные агентом значения с просьбой поправить фразой, ссылки на `outputs/one-pager.md`, `outputs/report.md`, `outputs/run-report.md` и строка статуса.
- `uv run strateg step done 7 --next 'выпуск готов; дальше: „что решать сейчас“ или „вот новые данные“'`. В итоговом сообщении — одна строка: «Дальше: „что решать сейчас“ или „вот новые данные“» (скиллы `follow-up` и `update`).

## Отказы, особые для шага
- `write` отказал: сообщение называет вид, запись и поле. Условие со строкой плана — пороги должны совпасть с `verification.yaml`.
- Документ противоречит файлу выхода — прав файл: исправь документ.
