# Шаг 1. Постановка (В1)

Цель: рамка задачи, которую человек принял. Без неё шаги 2а–7 строить не на чем.

## Вход
- `uv run strateg status`. Проекта нет или активный — о другой задаче: скилл `strateg`, раздел 4.
- Шаг 1 уже начат — `uv run strateg claim list --step 1` и `projects/<id>/sources.yaml`: допиши недостающее. `step start` повторяй только по правилу «Прервано» из `AGENTS.md`.
- В1 уже ждёт ответа, и сообщение человека — это ответ: иди к разделу «Ответ на В1».

## Работа
1. `uv run strateg step start 1`.
2. Прочитай запрос. Каждый файл из `inputs/` — `uv run strateg add '<путь>'`, затем читай его текст по пути из вывода (`AGENTS.md`, «Материалы и данные»). Ссылку из запроса открой сразу: исследователь по заданию «Нужно: снимок» (скилл `research`, раздел «Страница из запроса»). Исследователя нет — `uv run strateg fetch '<адрес>'`. Снимок читай сам. Это материал.
3. Составь черновик рамки и запиши его через `write` (формат ниже). Поля:
   - `decision` — решение, которое примут по итогам;
   - `decision_space` — варианты решения, не меньше двух;
   - `deadline` — срок решения;
   - `research_question` — вопрос исследования;
   - `recipient` — получатель документов;
   - `constraints` — ограничения;
   - `data` — какие данные есть;
   - `region` — регион аудитории;
   - `success_criteria` — критерии успеха;
   - `out_of_scope` — что вне рамки.
4. У каждого поля, кроме `decision_space`, — `value` и `origin`: `из запроса`, `из материалов`, `ответ человека` или `допущение`. Не знаешь — пиши допущение, не выдумывай «из запроса».
   - `из материалов` и `source: И-n` — только для источника, который CLI уже записал командой `fetch` или `add`. Материал, который ждёт `add --confirm`, источником не бывает.
5. В `decision` поставь рекомендуемый вариант с происхождением `допущение`: человек подтвердит или выберет другой.

   Метод и ситуации — `knowledge/methods/frame-and-questions.md`: прочитай, когда в запросе решение уже названо и выбирать не из чего.
6. По записанной рамке напиши `outputs/frame.md`. Разделы — по шаблону `knowledge/templates/frame.md`: заголовки и порядок не меняй, `<…>` замени текстом.

## Запись рамки
Файл — инструментом Write в `projects/<id>/.tmp/frame.yaml`, затем `uv run strateg write --file projects/<id>/.tmp/frame.yaml`. Тексты — в двойных кавычках (правило «Тексты во входах» из `AGENTS.md`), дату тоже.

```yaml
frame:
  decision: {value: "запускать ли доставку готовых обедов для офисов", origin: допущение}
  decision_space:
    - "запустить с предзаказом на день вперёд"
    - "запустить с заказом в день доставки"
    - не запускать
  deadline: {value: "к концу месяца", origin: из запроса}
  research_question: {value: "есть ли в городе спрос офисов на доставку обедов и что обещать по времени", origin: из запроса}
  recipient: {value: "руководитель направления", origin: допущение}
  constraints: {value: "только открытые источники", origin: из запроса}
  data: {value: "страница условий доставки конкурента по ссылке из запроса", origin: из материалов, source: И-1}
  region: {value: "один город", origin: допущение}
  success_criteria: {value: "решение с оценкой окупаемости и планом проверки на пилоте", origin: допущение}
  out_of_scope: {value: "подбор помещения под кухню", origin: допущение}
```

- `version` и `schema_version` не пиши: их ставит CLI.
- До ответа на В1 рамка — черновик. Каждая запись переписывает его на месте, версий нет.
- После ответа на В1 каждая правка — новая версия: прежняя уходит в `history/`.

## Ворота В1
В1 открывай всегда, в любом режиме. Сначала черновик записан, потом `uv run strateg gate open В1 --questions <N>`. Затем сообщение человеку:
- черновик рамки: поле, значение, откуда;
- не больше пяти вопросов, только о том, что открыто;
- вопрос о решении — выбором из вариантов с рекомендацией и причиной;
- в первом проекте — режим отдельной строкой, с рекомендацией автопилота; в `N` он не входит. Проект первый, если в `projects/` нет папок, кроме `example` и `demo`;
- бюджет по умолчанию: $5 или 60 минут работы, что наступит раньше;
- как ответить коротко, например «1а, ок»;
- строка статуса: `uv run strateg status --line`, дословно.

Остановись и жди ответа.

## Ответ на В1
1. Перепиши рамку по ответу: `uv run strateg write --file projects/<id>/.tmp/frame.yaml` с полным новым содержимым, без `--by`. Рамка ещё черновик, а ответ человека запишет `gate answer`; `--by пользователь` — только для правок после В1. Принятые допущения оставь с происхождением `допущение`, ответы человека пометь `ответ человека`.
2. Обнови `outputs/frame.md` и добавь блок «Было»: поле, прежнее значение, новое.
3. Допущения из рамки запиши в реестр: `uv run strateg claim add --file projects/<id>/.tmp/assumptions.yaml`. Формат допущения — в `.claude/skills/research/claims.md`. Слова человека — `origin: пользователь`, твои — `origin: агент`; `taken_from: ответ на В1`.
4. Фраза «пилот» или «автопилот» — `uv run strateg mode пилот` или `uv run strateg mode автопилот`.
5. `uv run strateg gate answer В1 --answer '<ответ человека дословно>'`. CLI копирует рамку в событие ворот.
6. `uv run strateg step done 1 --next 'шаг 2а: план исследования'`. Дальше — скилл `research`.

## «Уточни: …» после В1
- Покажи, что затронуто: вопросы плана, утверждения, варианты, разделы стратегий. Рядом — оценка стоимости и времени пересчёта.
- Ответившие ворота затронуты — жди подтверждения. Иначе пересчитывай сразу.
- Новая рамка: `uv run strateg write --file projects/<id>/.tmp/frame.yaml --by пользователь`. Версия растёт, прежняя остаётся в `history/`.
- Допущение изменилось — `uv run strateg claim replace У-<n> --file projects/<id>/.tmp/fix.yaml --by пользователь`.
- `outputs/frame.md` обнови, покажи «было → стало».

## Отказы, особые для шага
- `write` отказал: сообщение называет вид, запись и поле. `version` и `schema_version` из входа убери.
- `gate answer В1` отказал «рамки нет» — сначала `write`.
- Страница из запроса не открылась: `fetch` повторяется один раз (исследователем или тобой). Не открылась — данные из неё остаются допущением, запись CLI «источник недоступен» ляжет в пробел на шаге 3.
