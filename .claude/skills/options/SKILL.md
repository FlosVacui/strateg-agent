# Шаг 4. Варианты и возражения (В4)

Цель: честный выбор для человека. Варианты различаются по существу, возражения бьют по допущениям, рекомендация отвечает на сильнейшее из них.

## Вход
- `uv run strateg status`. Сводку `uv run strateg status --brief` здесь не вызывай: она — только в первом ходе нового чата, в скилле `strateg`. Картина готова (`outputs/situation.md`, `gaps.yaml`) — иначе сначала скилл `research`.
- `uv run strateg claim list --status действует`: на что можно опираться.
- `projects/<id>/options.yaml` уже есть — прочитай и допиши, не начинай заново. Возврат с В4 («сначала закрой П-n», «другой: …») — шаг уже начат, `step start` не вызывай. Исключение — сводка в начале разговора назвала шаг 4 прерванным: тогда `uv run strateg step start 4` ещё раз, иначе `step done 4` откажет.

## Работа
1. `uv run strateg step start 4`.
2. **Варианты.** Не меньше четырёх: «оставить как есть» (`kind: оставить как есть`), «закрыть направление» (для нового продукта `не запускать`) и не меньше двух активных. У каждого:
   - `differs`: ось (`аудитория`, `ценность` или `модель дохода`), ближайший вариант `from`, `how` — чем отличается. Масштаб, срок и бюджет осью не считаются. Пара, различающаяся только ими, — один вариант;
   - `main_assumption` — главное допущение;
   - у «оставить как есть» — `inaction_cost`, цена бездействия; у «закрыть» и «не запускать» — `return_condition`, условие возврата.
3. **Возражения.** У каждого варианта не меньше двух разных сильных. У возражения:
   - `hits_assumption` — какое допущение оно бьёт;
   - `drops_if` — что должно оказаться правдой, чтобы вариант отпал;
   - `basis` — номер `У-n` факта или гипотезы. Гипотезу сначала запиши через `claim add` (`basis` и `check_method`). Слово «гипотеза» без номера не пиши: у него нет способа проверки.
4. **Сравнение** по пяти критериям, без суммы баллов: эффект, затраты, риск, первый сигнал, обратимость.
   - Эффект и первый сигнал — прогнозы. Ячейка с текстом ссылается на `forecast: У-n` типа «прогноз» (диапазон, основания; как получен — в тексте утверждения).
   - Нет базы и нет аналога — прогноза нет. Ячейка пустая: в `why_empty` словами, какая база нужна и какой пробел `П-n`. Числовую уверенность не ставь. Рекомендацию на разнице таких ячеек не строй.
   - Обратимость с текстом — ещё `what` (механизм отката), `time` (срок), `price` (цена).
5. **Довод, который верен для любого варианта, вариант не различает.** В `why` рекомендации — довод про этот вариант, не про задачу вообще.
6. **Рекомендация**:
   - `option`, `why` и `claims` — номера утверждений, среди них хотя бы один факт. Синтетика основанием не служит. Число, которое компания сообщает о себе, — только как заявление компании;
   - `strongest_objection` — сильнейшее возражение против неё, `answer` — ответ по существу: довод, факт или условие, а не обход;
   - `change_mind` — что заставит передумать: показатель, порог с цифрой, действие;
   - `loses_on` — критерий, по которому рекомендованный вариант проигрывает.
7. **Перечитай как противник рекомендации.** Найди сильнейшее возражение, которое ты пропустил, и допиши его вариантам.
8. **Пробелы.** У каждого открытого пробела с `affects_choice: true` в `gaps.yaml` заполни `affects_options` номерами вариантов. Поэтому `gaps` и `options` пиши одним входом. Файл `write` заменяет целиком: присылай всё содержимое обоих.

Запись: `projects/<id>/.tmp/options.yaml`, затем `uv run strateg write --file projects/<id>/.tmp/options.yaml`. Вход: ключи `options` и `gaps`. Варианты — по этому образцу:

```yaml option
- id: Вар-2
  title: Продавать тренажёр отдельной подпиской
  kind: активный
  differs:
    axis: модель дохода
    from: Вар-3
    how: доход идёт отдельным платежом, а не через цену курса
  main_assumption: Студенты готовы платить за тренажёр отдельно
  objections:
    - hits_assumption: Студенты готовы платить за тренажёр отдельно
      drops_if: после пробного месяца подписку продлевает меньше десятой части
      basis: У-5
    - hits_assumption: Тренажёр нужен всем студентам
      drops_if: тренажёром пользуется меньше четверти студентов курса
      basis: У-3
  comparison:
    effect:
      text: Подписку оформят от 5 до 8 % студентов за год
      forecast: У-7
    cost:
      text: Разработка оплаты и поддержка подписчиков
    risk:
      text: Низкое продление после пробного месяца
    first_signal:
      why_empty: нет базы для диапазона, нужна доля продлений, см. П-1
    reversibility:
      text: Подписку можно закрыть
      what: снять подписку с продажи
      time: две недели
      price: уведомления подписчикам и возврат оплаты
```

Рекомендация:

```yaml recommendation
option: Вар-2
why: Отдельная подписка даёт доход там, где тренажёр используют, а цена в пределах обычной
claims: [У-2, У-7]
strongest_objection: Студенты не станут платить отдельно за то, что раньше входило в курс
answer: Пробный месяц и доля продлений покажут это до больших затрат
change_mind:
  - metric: доля продлений после пробного месяца
    threshold: ниже 20 %
    action: перейти к варианту Вар-3
loses_on: обратимость
```

## Документ `outputs/options.md`
Шаблон `knowledge/templates/options.md`, если он есть. Разделы:
- «Кратко» — 3–5 строк, сколько допущений принято, со ссылкой на `outputs/frame.md`;
- «Варианты» — таблица: номер, название, чем отличается, главное допущение;
- «Возражения» — по вариантам: допущение, что должно оказаться правдой, основание (например «У-12, факт»);
- «Сравнение» — таблица по пяти критериям; эффект и сигнал с пометкой «прогноз»; пустая ячейка — причина и `П-n`;
- «Рекомендация» — вариант, основания, сильнейшее возражение и ответ, «Передумаю, если»;
- «Пробелы, которые могут изменить выбор» — `П-n`, цена закрытия.

Числа и номера бери из `options.yaml`, `claims.yaml` и `gaps.yaml`, новых сведений не добавляй. Номера пиши русскими буквами.

## Ворота В4 (всегда)
`uv run strateg gate open В4 --questions 1`, затем сообщение:
- что сделано;
- рекомендация со ссылками на утверждения;
- таблица сравнения: варианты, пять критериев, сильнейшее возражение против каждого;
- сильнейшее возражение против рекомендации и ответ на него;
- «передумаю, если»: показатель и порог — они войдут в план проверки;
- пробелы, которые могут изменить выбор, и сколько стоит закрыть каждый;
- как ответить: номер варианта, «сначала закрой П-n» или «другой: …»;
- строка `uv run strateg status --line`, дословно.

Остановись и жди ответа. Режим не важен: В4 всегда с остановкой.

## После ответа
Сначала в любом случае `uv run strateg gate answer В4 --answer '<ответ человека дословно>'`.
- **Номер варианта.** Перепиши `options.yaml` с `chosen: Вар-<n>` (весь файл; прежний уйдёт в `history/`). Затем `uv run strateg step done 4 --next 'шаг 5: пре-мортем и стратегии'`. Дальше — скилл `strategy`.
- **«Сначала закрой П-n».** Шаг 4 не заканчивай. Закрой пробел по разделу «Шаг 2б» скилла `research` (`.claude/skills/research/SKILL.md`): поиск, `fetch`, `claim add`. Обнови `gaps.yaml` и затронутые варианты одним `write`, пересчитай сравнение и рекомендацию, покажи «было → стало» и снова открой `gate open В4 --questions 1`.
- **«Другой: …».** Добавь вариант с `differs`, возражениями и сравнением, обнови таблицу и рекомендацию, снова В4.
- Новые сведения противоречат рамке В1 или выбору — внеплановая остановка: `uv run strateg stop --reason '<что изменилось>'`, затем вопрос человеку.

## Правки человека
«В вариантах: …» после В4 — правка `options.yaml` (с `gaps`, если меняются ссылки) одним `write --by пользователь`, затем `outputs/options.md`. Затронут выбор на В4 — сначала покажи затронутое и жди подтверждения, по порядку пересчёта из `AGENTS.md`. Выбор человека сам не меняй.

## Отказы и сбои
- `write` отказал: сообщение называет вид, запись и поле. Исправь вход. «Ссылка на ещё не записанный файл» — пиши `gaps` и `options` одним входом.
- Ошибка инструмента: `uv run strateg event error --message '<что случилось>' --step 4 --tool <имя>`.
- Шаг не удался: `uv run strateg step fail 4 --reason '<причина>'`, скажи человеку.
