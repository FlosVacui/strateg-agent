# Шаг 4. Варианты и возражения (В4)

Цель: честный выбор для человека. Варианты различаются по существу, возражения бьют по допущениям, рекомендация отвечает на сильнейшее из них.

## Вход
- `uv run strateg status`. Картина готова (`outputs/situation.md`, `gaps.yaml`) — иначе сначала скилл `research`.
- `uv run strateg claim list --status действует`: на что можно опираться.
- `projects/<id>/options.yaml` уже есть — прочитай и допиши, не начинай заново. Возврат с В4 («сначала закрой П-n», «другой: …») — шаг уже начат, `step start` не вызывай.

## Работа
1. `uv run strateg step start 4`.
2. **Варианты.** Не меньше четырёх: «оставить как есть» (`kind: оставить как есть`), «закрыть направление» (для нового продукта `не запускать`) и не меньше двух активных. У каждого:
   - `differs`: ось (`аудитория`, `ценность` или `модель дохода`), ближайший вариант `from`, `how` — чем отличается. Масштаб, срок и бюджет осью не считаются. Пара, различающаяся только ими, — один вариант;
   - `main_assumption` — главное допущение;
   - у «оставить как есть» — `inaction_cost`, цена бездействия; у «закрыть» и «не запускать» — `return_condition`, условие возврата.
   - Метод и ситуации — `knowledge/methods/options.md`: прочитай, когда в запросе много идей или варианты выходят похожими друг на друга.
3. **Возражения.** У каждого варианта не меньше двух разных сильных. У возражения:
   - `hits_assumption` — какое допущение оно бьёт;
   - `drops_if` — что должно оказаться правдой, чтобы вариант отпал;
   - `basis` — номер `У-n` факта или гипотезы. Гипотезу сначала запиши через `claim add` (`basis` и `check_method`). Слово «гипотеза» без номера не пиши: у него нет способа проверки.
   - Метод и ситуации — `knowledge/methods/objections-and-premortem.md`: прочитай, когда возражения к варианту выходят парафразами одного или не опираются ни на факт, ни на гипотезу.
4. **Сравнение** по пяти критериям, без суммы баллов: эффект, затраты, риск, первый сигнал, обратимость.
   - Эффект и первый сигнал — прогнозы. Ячейка с текстом ссылается на `forecast: У-n` типа «прогноз» (диапазон, основания; как получен — в тексте утверждения).
   - Нет базы и нет аналога — прогноза нет. Ячейка пустая: в `why_empty` словами, какая база нужна и какой пробел `П-n`. Этот `П-n` должен быть записан в `gaps`: нет такого — оформи новый пробел (п. 9). Числовую уверенность не ставь. Рекомендацию на разнице таких ячеек не строй.
   - Обратимость с текстом — ещё `what` (механизм отката), `time` (срок), `price` (цена).
5. **Довод, который верен для любого варианта, вариант не различает.** В `why` рекомендации — довод про этот вариант, не про задачу вообще.
6. **Рекомендация**:
   - `option`, `why` и `claims` — номера утверждений, среди них хотя бы один факт не из источника «о себе». Синтетика основанием не служит;
   - `strongest_objection` — сильнейшее возражение против неё, `answer` — ответ по существу: довод, факт или условие, а не обход;
   - `change_mind` — что заставит передумать: показатель, порог с цифрой, действие;
   - `loses_on` — критерий, по которому рекомендованный вариант проигрывает.
7. **Перечитай как противник рекомендации.** Найди сильнейшее возражение, которое ты пропустил, и допиши его вариантам.
8. **Пробелы.** У каждого открытого пробела с `affects_choice: true` в `gaps.yaml` заполни `affects_options` номерами вариантов. Поэтому `gaps` и `options` пиши одним входом. `write` заменяет файл целиком: присылай всё содержимое обоих.
9. **Новый пробел на этом шаге** (нет базы для ячейки, нет числа) оформи как на шаге 3: до записи не меньше двух поисков с разными запросами, затем запись в `gaps` с `searched`, `affects_choice` и `affects_options` — в том же входе, что и вариант со ссылкой на него. Пробел с влиянием на выбор уйдёт на В4.

Запись: `projects/<id>/.tmp/options.yaml`, затем `uv run strateg write --file projects/<id>/.tmp/options.yaml`. Вход — ключи `options` и `gaps` (во втором заполнены `affects_options`). Образец ключа `options` в минимальном виде:

```yaml
options:
  options:
    - id: Вар-1
      title: "Оставить как есть"
      kind: оставить как есть
      differs: {axis: ценность, from: Вар-2, how: "офисной доставки по-прежнему нет"}
      main_assumption: "Офисные заказы не уходят к конкурентам"
      inaction_cost: "Постоянные офисные клиенты достаются конкурентам"
      objections:
        - {hits_assumption: "Офисные заказы не уходят к конкурентам", drops_if: "офисы массово переходят к конкурентам", basis: У-2}
        - {hits_assumption: "Доставка нам не нужна", drops_if: "офисы дают заметную долю заказов", basis: У-3}
      comparison:
        effect: {why_empty: "нет базы для диапазона: нужен спрос офисов, см. П-1"}
        cost: {text: "Затрат нет"}
        risk: {text: "Потеря офисных клиентов"}
        first_signal: {why_empty: "изменений нет, и сигнала нет"}
        reversibility: {text: "Запуск можно начать позже", what: "открыть доставку позже", time: "три месяца", price: "потеря времени"}
    - id: Вар-2
      title: "Запустить с предзаказом на день вперёд"
      kind: активный
      differs: {axis: аудитория, from: Вар-1, how: "появляются офисы как постоянные клиенты"}
      main_assumption: "Офисы готовы заказывать заранее"
      objections:
        - {hits_assumption: "Офисы готовы заказывать заранее", drops_if: "повторно заказывает меньше пяти офисов", basis: У-4}
        - {hits_assumption: "Кухня справится с пиком", drops_if: "опоздания превышают допустимые", basis: У-3}
      comparison:
        effect: {text: "Постоянными станут от 15 до 25 офисов за полгода", forecast: У-5}
        cost: {text: "Курьеры и упаковка"}
        risk: {text: "Низкая доля повторных заказов"}
        first_signal: {why_empty: "нет базы для срока первых повторов см. П-1"}
        reversibility: {text: "Доставку можно остановить", what: "снять доставку с продажи", time: "две недели", price: "уведомления офисам"}
    - id: Вар-3
      title: "Запустить с заказом в день доставки"
      kind: активный
      differs: {axis: ценность, from: Вар-2, how: "скорость вместо планирования"}
      main_assumption: "Офисы согласны платить за срочность"
      objections:
        - {hits_assumption: "Офисы согласны платить за срочность", drops_if: "срочные заказы редки", basis: У-4}
        - {hits_assumption: "Кухня успевает за час", drops_if: "средняя готовность дольше часа", basis: У-3}
      comparison:
        effect: {why_empty: "нет аналога для диапазона см. П-1"}
        cost: {text: "Резерв курьеров в пик"}
        risk: {text: "Срыв сроков в обеденный пик"}
        first_signal: {why_empty: "нет базы для срока см. П-1"}
        reversibility: {text: "Доставку можно остановить", what: "снять срочные заказы", time: "неделя", price: "потеря резерва курьеров"}
    - id: Вар-4
      title: "Не запускать"
      kind: не запускать
      differs: {axis: модель дохода, from: Вар-2, how: "нового дохода нет"}
      main_assumption: "Офисная доставка не окупится"
      return_condition: "Конкуренты уйдут из города или опрос офисов покажет спрос"
      objections:
        - {hits_assumption: "Офисная доставка не окупится", drops_if: "хватает пятнадцати постоянных офисов", basis: У-5}
        - {hits_assumption: "Конкуренты не усилятся", drops_if: "конкурент открывает офисную доставку", basis: У-2}
      comparison:
        effect: {why_empty: "прогноз эффекта не нужен — изменений нет"}
        cost: {text: "Затрат нет"}
        risk: {text: "Конкуренты займут рынок"}
        first_signal: {why_empty: "изменений нет, и сигнала нет"}

    option: Вар-2

    strongest_objection: "Офисы не будут заказывать заранее"
    answer: "Пробный месяц покажет долю повторных предзаказов до затрат на кухню"
    change_mind:
      - {metric: "число офисов с повторным заказом за месяц", threshold: "меньше 5 офисов", action: "перейти к варианту Вар-3"}
    loses_on: затраты
```

Ячейка критерия — либо `text`, либо `why_empty` (не короче десяти знаков, словами). Выбор человека в этот вход не входит: поле `chosen` появляется после ответа на В4.

## Документ `outputs/options.md`
Разделы — по шаблону `knowledge/templates/options.md`: заголовки и порядок не меняй, `<…>` замени текстом.

Числа и номера бери из `options.yaml`, `claims.yaml` и `gaps.yaml`, новых сведений не добавляй. Номера пиши русскими буквами.

## Ворота В4 (всегда)
`uv run strateg gate open В4 --questions 1`, затем сообщение:
- что сделано;
- рекомендация со ссылками на утверждения;
- таблица сравнения: варианты, пять критериев, сильнейшее возражение против каждого;
- сильнейшее возражение против рекомендации и ответ на него;
- «передумаю, если»: показатель и порог — они войдут в план проверки;
- пробелы, которые могут изменить выбор, и сколько стоит закрыть каждый;
- как ответить: номер варианта, «сначала закрой П-n» или «другой: …»;
- строка `uv run strateg status --line`, дословно.

Остановись и жди ответа. Режим не важен: В4 всегда с остановкой.

## После ответа
Сначала в любом случае `uv run strateg gate answer В4 --answer '<ответ человека дословно>'`.
- **Номер варианта.** Перепиши `options.yaml` с `chosen: Вар-<n>` рядом с `options` и `recommendation` (весь файл; прежний уйдёт в `history/`). Затем `uv run strateg step done 4 --next 'шаг 5: пре-мортем и стратегии'`. Дальше — скилл `strategy`.
- **«Сначала закрой П-n».** Шаг 4 не заканчивай. Закрой пробел по разделу «Шаг 2б» скилла `research` (`.claude/skills/research/SKILL.md`): поиск, `fetch`, `claim add`. Обнови `gaps.yaml` и затронутые варианты одним `write`, пересчитай сравнение и рекомендацию, покажи «было → стало» и снова открой `gate open В4 --questions 1`.
- **«Другой: …».** Добавь вариант с `differs`, возражениями и сравнением, обнови таблицу и рекомендацию, снова В4.
- Новые сведения противоречат рамке В1 или выбору — внеплановая остановка: `uv run strateg stop --reason '<что изменилось>'`, затем вопрос человеку: пересматривать ли выбор. Ответ — по разделу «Пересмотр выбора».

## Пересмотр выбора
Сюда ведут две остановки: причина пре-мортема (шаг 5) и новые сведения против выбора или рамки.
- **«Пересмотреть».** Порядок пересчёта из `AGENTS.md`: покажи затронутое и «было → стало» по вариантам и стратегиям. Это шаг 4 заново: `uv run strateg step start 4`. Поправь `options.yaml` (возражения, сравнение, рекомендация) через `write`; новые сведения сначала запиши через `claim add`. Затем `gate open В4 --questions 1` с причиной остановки в сообщении, `gate answer В4`, новый `chosen` через `write`, `step done 4`. Дальше — скилл `strategy`, шаг 5 заново: пересчитай его записи по порядку.
- **«Оставить».** Выбор не меняй. Причина остаётся с `hits_choice: true`, в отчёте о прогоне — в «Помощи человека». Продолжай шаг, на котором остановился.
- Новые сведения противоречат рамке В1 — «уточни» через скилл `frame` и порядок пересчёта.

## Правки человека
«В вариантах: …» после В4 — правка `options.yaml` (с `gaps`, если меняются ссылки) одним `write --by пользователь`, затем `outputs/options.md`. Затронут выбор на В4 — сначала покажи затронутое и жди подтверждения, по порядку пересчёта из `AGENTS.md`. Выбор человека сам не меняй.

## Отказы, особые для шага
- `write` отказал: сообщение называет вид, запись и поле. «Ссылка на ещё не записанный файл» — пиши `gaps` и `options` одним входом.
